# Project Doc Sync

## 이 스킬을 언제 쓰이나?

- **대화 종료 후**: 구현 변경 사항을 문서에 반영할 때
- **새 기능 추가 후**: API/스키마 문서 업데이트
- ** deploy 후**: 체크리스트나 환경 설정 문서 갱신
- **정기 정합성 확인**: 전체 문서 검토 시

## 입력으로 필요한 것

| 항목 | 필수 | 설명 |
|------|------|------|
| 대상 문서 유형 | 필수 | roadmap/tech/ops 등 |
| 변경 사항 | 필수 | 구현과 다른 부분 |
| 현재 상태 | 필수 | 코드 기반 현재 구현 |

## 출력 결과

- 갱신된 문서 (`docs/` 하위)
- 불필요한 과거 계획 제거
- 현재 상태 우선 정리

## 문서 유형별 책임

| 유형 | 대상 문서 | 갱신 주기 |
|------|----------|----------|
| **roadmap** | `docs/ROADMAP.md` | 기능 완료 시 |
| **tech** | `docs/tech/DB_SCHEMA.md`, `API_CONTRACT.md` | 스키마 변경 시 |
| **product** | `docs/product/UI_STATES.md`, `USER_FLOW.md` | UI 변경 시 |
| **ops** | `docs/ops/DEPLOY_CHECKLIST.md`, `ENV_DEPENDENCY.md` | deploy 후 |

## 작업 원칙

> **중요**: LoveBud는 **컴2 (작업 사본)** 가 기준입니다.
> - 원본(컴1)의 문서와 다를 수 있음
> - 구현과 문서가 다르면 **문서가 아니라 구현을 기준**으로 함
> - 과거 계획보다 현재 상태 우선

### 구체 규칙

1. **구현 vs 문서 불일치**: 구현을 기준으로 문서 수정
2. **삭제할 내용**: "추후 구현 예정"이지만 실제로 안 하는 것
3. **유지할 내용**: 현재 실제로 동작하는 것
4. **새로 추가**: 최근 커밋으로 새로 된 것

## 작업 흐름

### 1. 대상 문서 확인

```bash
# 문서 목록 확인
ls docs/
ls docs/tech/
ls docs/ops/

# 최근 변경된 문서 확인
git log --oneline -10 -- docs/
```

### 2. 현재 구현 상태 파악

```bash
# 관련 코드 확인
git diff HEAD~5 -- netlify/functions/

# API 엔드포인트 확인
grep -r "exports.handler" netlify/functions/
```

### 3. 불일치 사항 정리

| 구분 | 처리 |
|------|------|
| 구현 != 문서 | 문서를 구현에 맞춤 |
| 과거 계획 | 삭제 또는 "제거됨" 표시 |
| 현재 상태 | 현재 기준으로 기술 |

### 4. 문서 갱신

```markdown
## 변경 사항

### 변경 전
{과거 문구}

### 변경 후
{현재 구현}

### 이유
{왜 변경했는지}
```
