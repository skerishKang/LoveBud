# Page Doc Writer

## 이 스킬을 언제 쓰이나?

- **페이지 구현 후**: 새로운 페이지나 기능 완성 시
- **브라우저 검증 후**: QA 결과 정리 시
- **기능 수정 후**: 주요 버그 수정이나 기능 변경 시

## 입력으로 필요한 것

| 항목 | 필수 | 설명 |
|------|------|------|
| 페이지 이름 | 필수 | 검색/상세/에디터 등 |
| 관련 파일 | 필수 | HTML, JS 파일 경로 |
| 브라우저 검증 결과 | 선택 | QA 통과/실패 내용 |
| 최근 커밋 | 선택 | 커밋 해시/메시지 |

## 출력 결과

| 파일 | 위치 |
|------|------|
| 페이지 문서 | `docs/pages/<page-name>.md` |
| 페이지 인덱스 | `docs/pages/pages_index.md` (갱신) |

## 문서에 반드시 들어갈 항목

```
1. 페이지 목적 - 이 페이지가 무엇을 하는지
2. 사용자 목표 - 사용자가 무엇을 할 수 있는지
3. 현재 구현 상태 - 파일 구조, 주요 기능
4. 잘 되는 것 - ✅ 통과한 기능 목록
5. 현재 문제/리스크 - ❌ 문제점, ⚠️ 리스크
6. 주요 UI 섹션 - 헤더, 콘텐츠, 푸터 등
7. 상태별 화면 - 로딩/빈 상태/성공/에러
8. 필요한 데이터/API - 백엔드 의존성
9. 다음 개선 포인트 - 로드맵
```

## 작업 흐름

### 1. 페이지 파일 분석

```bash
# 관련 파일 확인
ls pages/<page>.html
ls js/<page>.js

# 최근 커밋 확인
git log --oneline -5 -- js/<page>.js pages/<page>.html
```

### 2. 현재 구현 상태 파악

- 파일 구조 (inline CSS/JS 여부)
- 주요 함수/클래스
- API 호출 패턴
- 상태 관리 방식

### 3. 브라우저 검증 결과 정리

- ✅ 잘 되는 기능
- ❌ 실패한 기능
- ⚠️ 주의 필요

### 4. 문서 작성

```markdown
# <page-name> (<page-title>)

## 페이지 목적
...

## 사용자 목표
1. ...
2. ...

## 현재 구현 상태
### 주요 UI 섹션
- ...

### 현재 파일 구조
- ...

### 주요 기능
- ...

---

## 현재 잘 되는 것

| 항목 | 상태 |
|------|------|
| ... | ✅ |

---

## 현재 문제/리스크

| 문제 | 설명 |
|------|------|
| ... | ... |
```
