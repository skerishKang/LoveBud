# Full 전문 처리 원칙

**파일명**: `docs/conversation/full/YYYY-MM-DD-NN-짧은제목.md`

## 핵심 원칙

`full/` 문서는 가능한 한 **새로 작성하지 않습니다.**

이 폴더의 목적은:
- 세션 대화 **원문 보존**
- 세션 복구용 **1차 자료 저장**
- summary 작성 전, 원본 근거 유지

따라서 입력으로 이미 대화 전문 파일이 있으면 다음 순서를 우선합니다.

1. 기존 `full/` 문서들과 **중복 여부 확인**
2. 중복이 아니면 **원문 그대로 rename / move**
3. 필요할 때만 아주 최소한의 메타데이터 보강 검토
4. 원문을 summary처럼 다시 쓰지 말 것

## 허용되는 처리

- `root.txt`, `root1.txt` 같은 임시 파일명을 정식 파일명으로 변경
- `docs/conversation/full/` 아래로 이동
- 인덱스 링크 갱신
- summary 작성에 필요한 날짜/세션 번호/짧은 제목 판별

## 지양할 처리

- full 문서를 새로 요약해서 다시 작성
- 원문을 임의로 문단 정리하거나 의미를 재구성
- 결정사항/커밋/파일변경 표를 full 문서 본문에 덧붙여 원문성을 훼손

## 예외

입력에 전문 파일이 아예 없고, 대화 내용 일부만 전달된 경우에만
`full` 문서를 새로 구성할 수 있습니다.

그 경우에도:
- 가능한 원문 순서를 유지
- 해석/요약은 최소화
- 분석 내용은 `summary/`에 두는 것을 우선

- 기존 full 문서와 중복인가?
- 새 문서 생성이 아니라 rename / move로 해결 가능한가?
- 원문 보존 원칙을 지켰는가?
