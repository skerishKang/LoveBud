# CORE-NEWUSER-001

이 문서는 현재 LoveBud / LoveTree 기준의 대표 테스트 시나리오입니다.

목적은 처음 방문한 사용자가 서비스 목적을 이해하고, 로그인 후 `my-trees → editor`로 진입해 첫 트리와 첫 순간을 만들고, 저장 이후에도 상태가 일관적으로 유지되는지 검증하는 것입니다.

---

## 1. 왜 이 시나리오가 중요한가

신규 사용자는 제품 구조를 모릅니다. 따라서 첫 사용 흐름에서는 아래가 한 번에 맞아야 합니다.

- 첫 화면에서 서비스 목적이 이해되는지
- 로그인 진입과 완료가 자연스러운지
- 로그인 후 `my-trees`에 안착하는지
- 첫 트리 생성과 editor 진입이 자연스러운지
- 첫 루트 순간이 캔버스/좌측/우측에서 일관적으로 보이는지
- 언어 전환이 `my-trees`, `editor`까지 실제 반영되는지
- 첫 순간 저장 후 재진입해도 상태가 유지되는지

이 중 하나라도 흔들리면 첫 사용 전환이 크게 떨어질 수 있습니다.

---

## 2. 테스트 범위

### 대상 페이지
- 루트 랜딩
- 로그인 페이지
- my-trees
- editor
- 필요 시 detail

### 핵심 검증 질문
- 서비스 목적이 첫 화면에서 이해되는가
- 로그인 후 `my-trees`가 자연스러운 첫 안착 지점인가
- 새 트리 생성 후 editor 진입이 자연스러운가
- 첫 루트 순간 상태가 캔버스/좌측/우측 패널에서 서로 모순되지 않는가
- 언어 전환이 header뿐 아니라 `my-trees`, `editor` 본문까지 반영되는가
- 첫 순간 저장 후 상태 불일치 없이 유지되는가

---

## 3. 사전 준비 (Clean Start 원칙)

1. 이미 로그인된 상태라면 반드시 로그아웃합니다.
2. 브라우저의 `LocalStorage`, `IndexedDB`를 삭제하여 신규 방문자 상태로 만듭니다.
3. 가능하면 인코그니토 창에서 시작합니다.

### 테스트 데이터
`docs/test-scenarios/data/{group}-data.json` 중 하나를 사용합니다.

### 결과 폴더 권장 형식
`docs/test-scenarios/results/core-newuser-001-{group}-YYYY-MM-DD-HHMM/`

### 결과 파일
- `test-result.md`
- 필요 시 `screenshots/*.png`

## 4. 단계

### STEP 1. 첫 화면 이해
행동:
- 첫 화면에 접속한다.
- 3초 정도 보고 이 서비스가 무엇을 하는지 한 문장으로 말해본다.

기대 결과:
- 팬 감정 기록 서비스라는 목적이 이해된다.
- 시작 CTA와 둘러보기 CTA의 역할 차이가 이해된다.
- 로그인을 강요하기 전에 공개 감상과 개인 시작의 두 경로가 구분된다.

기록 항목:
- 첫 인상
- 3초 이해 가능 여부
- 가장 헷갈린 문구 1개

### STEP 2. 로그인 진입 및 완료
행동:
- 시작 CTA 또는 로그인 진입 버튼을 사용해 로그인한다.

기대 결과:
- 로그인 버튼을 찾기 어렵지 않다.
- 인증 과정이 멈추지 않는다.
- 로그인 완료 후 사용자가 어디로 이동했는지 명확하다.

기록 항목:
- 버튼 발견 시간
- 완료 여부
- 에러 발생 여부

### STEP 3. 로그인 후 my-trees 안착
행동:
- 로그인 완료 직후 도착한 화면을 확인한다.
- `my-trees` 페이지 기준으로 첫 행동을 파악한다.

기대 결과:
- 신규 사용자는 빈 상태 또는 첫 트리 생성 CTA를 본다.
- 빈 상태 문구가 추상적이지 않고, 다음 행동이 명확하다.
- 공개/비공개 요약 또는 헤더가 잘못된 기존 데이터처럼 보이지 않는다.

기록 항목:
- 이동한 페이지
- 첫 행동 명확성
- 빈 상태 이해도

### STEP 4. 언어 전환 확인 (my-trees)
행동:
- Shared Header에서 언어를 전환한다.
- `my-trees` 본문 제목, 설명, CTA, 빈 상태 문구를 확인한다.

기대 결과:
- header만 바뀌고 본문은 남는 식의 부분 번역이 없어야 한다.
- 제목, 설명, 빈 상태, 생성 버튼이 함께 바뀌어야 한다.
- 언어 전환 후 레이아웃이 심하게 무너지지 않는다.

기록 항목:
- 전환 전/후 언어
- 본문 반영 여부
- 레이아웃 이상 여부

### STEP 5. 첫 트리 생성 및 editor 진입
행동:
- `my-trees`에서 새 트리 만들기 CTA를 눌러 첫 트리를 만든다.
- 생성 직후 editor로 이동하는지 본다.

기대 결과:
- 새 트리 만들기 액션을 바로 찾을 수 있다.
- 생성 후 editor로 자연스럽게 이동한다.
- 이동 직후 로그인 지연/권한 지연 때문에 빈 화면으로 머물지 않는다.

기록 항목:
- 클릭 수
- 생성 성공 여부
- 생성 직후 도착 화면

### STEP 6. 첫 루트 상태 일관성 확인
행동:
- 첫 트리 생성 직후 editor 초기 상태를 본다.

기대 결과:
- 루트 노드가 캔버스에 보이면, 좌측 상태 요약과 우측 패널도 같은 기준으로 설명한다.
- "노드는 보이는데 0개" 또는 "노드는 보이는데 첫 순간 대기" 같은 모순이 없어야 한다.
- 우측 패널의 공개/비공개 배지와 트리 상태 설명이 서로 충돌하지 않는다.

기록 항목:
- 캔버스 상태
- 좌측 상태 문구
- 우측 패널 상태 문구
- 모순 여부

### STEP 7. 언어 전환 확인 (editor)
행동:
- editor에서 언어를 다시 전환한다.
- 좌측 흐름 영역, 우측 패널 제목/설명, 버튼 문구를 확인한다.

기대 결과:
- Shared Header뿐 아니라 editor 본문 주요 문구도 함께 바뀐다.
- 좌측 상태/우측 패널/버튼 문구가 서로 다른 언어로 섞이지 않는다.
- 전환 후 선택 상태나 루트 상태가 초기화되지 않는다.

기록 항목:
- 본문 반영 여부
- 언어 혼합 여부
- 상태 유지 여부

### STEP 8. 첫 순간 입력 및 저장
행동:
- 테스트 데이터의 URL 1개를 사용한다.
- 제목과 감정 메모를 입력하고 저장한다.

기대 결과:
- 입력 필드 의미가 분명하다.
- 잘못된 URL이면 이해 가능한 검증 문구가 나온다.
- 저장 후 캔버스, 좌측 요약, 우측 패널이 같은 새 상태를 말한다.

기록 항목:
- 사용 데이터
- 저장 성공 여부
- 저장 직후 상태 일치 여부

### STEP 9. 새로고침 및 재진입 확인
행동:
- editor를 새로고침한다.
- `my-trees`로 돌아갔다가 같은 트리에 다시 들어간다.

기대 결과:
- 방금 만든 첫 순간이 유지된다.
- `my-trees`와 editor가 서로 다른 상태를 말하지 않는다.
- 재진입 후에도 우측 패널이 빈 상태나 대기 상태로 잘못 돌아가지 않는다.

기록 항목:
- 새로고침 후 유지 여부
- `my-trees ↔ editor` 일관성
- 최종 판단

## 5. 에지 체크

시간이 허용하면 아래를 함께 확인합니다.

- 잘못된 YouTube 링크 입력 시 검증 문구 이해 가능
- 저장 버튼 연타 시 중복 생성 없음
- 뒤로가기 후 다시 editor 진입 가능
- 로그인 직후 첫 생성 시 권한 지연 없음
- 첫 루트 상태에서 감정 태그/메모 fallback이 지나치게 건조하지 않음

## 7. 판정 기준

통과:
- 신규 사용자가 큰 도움 없이 로그인 후 첫 트리와 첫 순간을 완료한다.
- 첫 루트 상태와 첫 저장 상태가 캔버스/좌측/우측에서 일관된다.
- 언어 전환이 `my-trees`, `editor` 본문까지 반영된다.

조건부 통과:
- 완료는 가능하지만 언어 반영, 상태 문구, 다음 행동 안내에서 혼란이 있다.

실패:
- 첫 트리 생성 또는 첫 순간 저장을 끝내지 못한다.
- 루트 노드가 보이는데 좌측/우측이 빈 상태처럼 말한다.
- 새로고침 또는 재진입 후 상태가 크게 어긋난다.
