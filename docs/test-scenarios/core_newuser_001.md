# CORE-NEWUSER-001

이 문서는 현재 LoveBud / LoveTree 기준의 대표 테스트 시나리오입니다.

목적은 단순히 화면이 열리는지 확인하는 것이 아니라, 처음 방문한 사용자가 서비스 목적을 이해하고, 로그인 후 첫 트리를 만들고, 첫 메모리를 저장하고, 다시 확인하는 흐름 전체가 자연스럽게 완료되는지 검증하는 것입니다.

---

## 1. 왜 이 시나리오가 중요한가

신규 사용자는 제품 내부 구조를 모릅니다.
신규 사용자가 보는 것은 다음 순서뿐입니다.

- 첫 화면에서 무엇을 하는 서비스인지 이해할 수 있는지
- 어디를 눌러야 시작되는지
- 로그인 후 어디로 이동하는지
- 첫 트리를 어떻게 만드는지
- 첫 메모리를 어떻게 저장하는지
- 저장한 데이터가 실제로 남는지

이 중 하나라도 흔들리면 첫 사용 전환이 크게 떨어질 수 있습니다.
따라서 이 문서는 릴리스 전 최소 세트의 핵심 문서로 사용합니다.

---

## 2. 테스트 범위

### 대상 페이지
- 루트 랜딩
- 로그인 페이지
- my-trees
- editor
- 필요 시 detail

### 핵심 검증 질문
- 서비스 목적이 첫 화면에서 이해되는가
- 로그인 진입과 완료가 자연스러운가
- 로그인 후 첫 화면 안착이 적절한가
- 첫 트리 생성이 쉬운가
- 첫 메모리 입력과 저장이 가능한가
- 저장 후 데이터가 유지되는가

---

## 3. 사전 준비 (Clean Start 원칙)

본 시나리오는 신규 사용자의 경험을 검증하므로, 반드시 아래의 **클린 스타트** 과정을 거쳐야 합니다.

1. **로그아웃 확인**: 이미 로그인된 상태라면 반드시 로그아웃을 수행합니다.
2. **세션/캐시 초기화**: 브라우저의 `LocalStorage` 및 `IndexedDB`(Firebase 세션 저장소)를 삭제하여 완전히 새로운 방문자 상태로 만듭니다.
3. **인코그니토 권장**: 가능하면 인코그니토(시크릿) 창에서 테스트를 시작합니다.

### 테스트 데이터
`docs/test-scenarios/data/{group}-data.json` 중 하나를 사용합니다.

### 결과 폴더 권장 형식
`docs/test-scenarios/results/core-newuser-001-{group}-YYYY-MM-DD-HHMM/`

### 결과 파일
- test-result.md
- 필요 시 스크린샷

## 4. 단계

### STEP 1. 첫 화면 이해
행동:
- 첫 화면에 접속한다.
- 3초 정도 보고 이 서비스가 무엇을 하는지 한 문장으로 말해본다.

확인 포인트:
- 서비스 목적이 바로 이해되는가 (나만의 러브트리 가치 전달)
- 메인 CTA인 **"나의 첫 러브트리 만들기"** 버튼이 명확히 보이는가
- "둘러보기"와 "시작하기"의 차이가 직관적인가 (현재 UI 상에서는 '나의 첫 러브트리 만들기'와 '예시 트리 먼저 보기')

기록 항목:
- 첫 인상
- 3초 이해 가능 여부
- 혼란 포인트

### STEP 2. 로그인 진입
행동:
- **"나의 첫 러브트리 만들기"** 버튼 또는 상단 로그인 버튼을 누른다.
- 인증 절차를 완료한다.

확인 포인트:
- 버튼을 찾기 쉬운가
- 인증 중 멈춤이 없는가
- 완료 후 성공 여부를 확신할 수 있는가

기록 항목:
- 버튼 발견 시간
- 완료 여부
- 에러 발생 여부
- 혼란 포인트

### STEP 3. 로그인 후 첫 화면 안착
행동:
- 로그인 완료 직후 이동한 페이지를 본다.

확인 포인트:
- 예상한 페이지로 이동하는가
- 다음 행동이 제시되는가
- 사용자 상태 UI가 자연스러운가

기록 항목:
- 이동한 페이지
- 기대와 일치 여부
- 다음 행동 명확성

### STEP 4. 첫 트리 생성
행동:
- 첫 트리를 만든다.

확인 포인트:
- 새 트리 만들기 액션을 바로 찾을 수 있는가
- 생성 후 이동이 자연스러운가
- 성공 여부를 알 수 있는가

기록 항목:
- 클릭 수
- 생성 성공 여부
- 직관성 점수
- 생성 직후 화면

### STEP 5. 첫 메모리 입력
행동:
- 테스트 데이터의 URL 1개를 사용한다.
- 제목, 설명, 태그가 있으면 함께 입력한다.
- 저장을 시도한다.

확인 포인트:
- 입력 필드 의미가 분명한가
- 검증 메시지가 이해 가능한가
- 저장 피드백이 자연스러운가

기록 항목:
- 사용 데이터
- 입력 난이도
- 저장 성공 여부
- 막힌 지점

### STEP 6. 저장 결과 확인
행동:
- 방금 만든 메모리가 실제로 보이는지 확인한다.

확인 포인트:
- 즉시 표시되는가
- 제목, 썸네일, 메타데이터가 정상인가
- 저장됐다는 확신을 줄 수 있는가

기록 항목:
- 즉시 표시 여부
- 렌더링 이상 여부
- 저장 신뢰도

### STEP 7. 새로고침 / 재진입 확인
행동:
- 페이지를 새로고침한다.
- 다시 트리 또는 에디터에 진입한다.

확인 포인트:
- 방금 만든 데이터가 남아 있는가
- 목록과 에디터가 일관적인가
- 캐시와 실제 상태가 심하게 어긋나지 않는가

기록 항목:
- 새로고침 후 유지 여부
- 재진입 후 일관성 여부
- 최종 판단

## 5. 에지 체크

시간이 허용하면 아래를 함께 확인합니다.

- 잘못된 링크 입력 시 안내 문구 이해 가능
- 저장 버튼 연타 시 이상 중복 없음
- 뒤로가기 후 다시 진입 가능
- 로그인 직후 첫 생성 시 권한 지연 없음

## 7. 판정 기준

통과:
- 신규 사용자가 큰 도움 없이 첫 트리와 첫 메모리를 완료한다.
- 저장과 재진입에서 치명적인 불일치가 없다.

조건부 통과:
- 완료는 가능하지만 중간 혼란이 크다.
- UX 문제는 있으나 치명적 실패는 없다.

실패:
- 첫 트리 생성 또는 첫 메모리 저장을 끝내지 못한다.
- 로그인 상태와 실제 데이터 상태가 크게 어긋난다. (예: 신규 가입인데 기존 트리가 보임)
- 저장 후 데이터가 사라진다.
