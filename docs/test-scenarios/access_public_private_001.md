# ACCESS-PUBLIC-PRIVATE-001

이 문서는 공개/비공개 경계와 소유자 권한을 검증하는 현재 대표 시나리오입니다.

목적은 공개 트리와 비공개 트리, 공개 메모리와 비공개 메모리, 소유자와 비소유자, 로그인 사용자와 비로그인 사용자 사이의 접근 차이가 기대대로 동작하는지 확인하는 것입니다.

---

## 1. 왜 중요한가

권한 문제는 UI가 예뻐도 신뢰를 바로 무너뜨릴 수 있습니다.
특히 LoveBud는 공개 탐색과 개인 기록이 함께 존재하므로, 다음 경계가 명확해야 합니다.

- 비로그인 사용자는 무엇까지 볼 수 있는가
- 로그인 사용자는 자기 것이 아닌 비공개 데이터에 접근할 수 없는가
- 소유자는 자기 데이터에 대해 수정/삭제가 가능한가
- 공개 데이터는 browse 흐름에서 자연스럽게 노출되는가

---

## 2. 범위

핵심 질문:
- 공개 데이터는 기대한 곳에서 보이는가
- 비공개 데이터는 외부에서 차단되는가
- 소유자 권한은 충분히 보장되는가
- 차단 시 메시지나 화면이 자연스러운가

---

## 3. 사전 준비

최소 준비 데이터:
- 공개 트리 1개
- 비공개 트리 1개
- 각 트리에 공개/비공개 메모리 상태가 확인 가능한 데이터
- 소유자 계정과 비소유자 계정 또는 비로그인 상태

결과 폴더 권장 형식:
`docs/test-scenarios/results/access-public-private-001-YYYY-MM-DD-HHMM/`

---

## 4. 단계

### STEP 1. 비로그인 공개 탐색
행동:
- 비로그인 상태에서 search 또는 공개 진입 경로를 사용한다.

확인 포인트:
- 공개 트리만 노출되는가
- 비로그인 사용자가 제품 가치를 이해할 수 있는 범위는 제공되는가
- 비공개 데이터가 섞여 보이지 않는가

기록 항목:
- 공개 노출 범위
- 비공개 누출 여부

### STEP 2. 비로그인 직접 진입 차단
행동:
- 비공개 트리 또는 비공개 메모리에 직접 진입을 시도한다.

확인 포인트:
- 접근이 차단되는가
- 404, 403, 빈 화면, 강제 리다이렉트 중 어떤 형태인지 일관적인가
- 사용자 관점에서 너무 이상하지 않은가

기록 항목:
- 차단 방식
- 사용자 메시지
- 화면 안정성

### STEP 3. 비소유자 로그인 상태 점검
행동:
- 비소유자 계정으로 로그인한 후 비공개 데이터 접근을 시도한다.

확인 포인트:
- 비공개 데이터가 보이지 않는가
- 소유자 전용 수정 UI가 나타나지 않는가
- 공개 데이터만 접근 가능한가

기록 항목:
- 비소유자 접근 결과
- 잘못 노출된 UI 여부

### STEP 4. 소유자 접근 확인
행동:
- 소유자 계정으로 로그인한 후 자기 트리와 메모리를 연다.

확인 포인트:
- 자기 비공개 데이터 접근 가능
- 수정/삭제 관련 액션 사용 가능
- 공개/비공개 상태가 기대대로 보이는가

기록 항목:
- 소유자 접근 결과
- 수정 가능 여부

### STEP 5. 공개 전환 / 비공개 전환 후 반영
행동:
- 가능하다면 트리 또는 메모리 공개 범위를 바꾼다.
- browse 또는 직접 진입에서 반영 여부를 본다.

확인 포인트:
- 전환 후 노출 범위가 바뀌는가
- 캐시 때문에 오래된 권한 상태가 남지 않는가

기록 항목:
- 전환 반영 속도
- 캐시 혼선 여부

---

## 5. 에지 체크

- 공개 트리 안 비공개 메모리 경계가 어색하지 않은가
- detail 직접 진입 시 권한 체크가 일관적인가
- 비공개 데이터 차단 시 UI가 너무 깨지지 않는가

---

## 6. 최종 판정

통과:
- 공개와 비공개, 소유자와 비소유자 경계가 일관되게 유지된다.

조건부 통과:
- 데이터 누출은 없지만 차단 UX가 다소 거칠다.

실패:
- 비공개 데이터가 보이거나, 소유자 전용 액션이 잘못 노출되거나, 권한 상태가 심하게 혼선된다.
