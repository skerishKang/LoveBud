# ACCESS-PUBLIC-PRIVATE-001

이 문서는 공개/비공개 경계와 소유자 권한을 검증하는 현재 대표 시나리오입니다.

목적은 공개 트리와 비공개 트리, browse 노출, detail 직접 진입, editor 소유자 권한, 공개 전환 후 반영 여부가 현재 제품 기준으로 일관되게 동작하는지 확인하는 것입니다.

---

## 1. 왜 중요한가

LoveTree는 공개 감상과 개인 기록이 함께 존재합니다. 따라서 아래 경계가 분명해야 신뢰가 유지됩니다.

- 공개 트리는 browse에서 보여야 한다.
- 비공개 트리는 browse에 보이면 안 된다.
- 비로그인/비소유자는 비공개 트리에 접근할 수 없어야 한다.
- 소유자는 자기 트리를 editor에서 정상 편집할 수 있어야 한다.
- 공개/비공개 상태를 바꾸면 browse 노출 결과도 그에 맞게 달라져야 한다.

---

## 2. 범위

### 핵심 질문
- 공개 트리와 비공개 트리의 browse 노출 결과가 일치하는가
- detail 직접 진입 시 권한 경계가 일관적인가
- 소유자와 비소유자에게 보이는 UI가 다르게 동작하는가
- 공개 상태 전환 후 browse 반영이 이어지는가
- 필요 시 트리 공개와 순간 공개 집계 관계를 확인할 수 있는가

---

## 3. 사전 준비

최소 준비 데이터:
- 공개 트리 1개
- 비공개 트리 1개
- 가능하면 공개 트리 안 대표 순간/preview가 있는 데이터 1개
- 소유자 계정
- 비소유자 계정 또는 비로그인 상태

결과 폴더 권장 형식:
`docs/test-scenarios/results/access-public-private-001-YYYY-MM-DD-HHMM/`

---

## 4. 단계

### STEP 1. 비로그인 browse 공개 노출 확인
행동:
- 비로그인 상태에서 search/browse에 진입한다.

기대 결과:
- 공개 트리만 노출된다.
- 비공개 트리는 카드, preview, 검색 결과 어디에도 섞여 보이지 않는다.
- 공개 트리가 존재하는데 browse 전체 empty state가 잘못 뜨지 않는다.

기록 항목:
- 공개 노출 범위
- 비공개 누출 여부
- empty state 이상 여부

### STEP 2. 비로그인 직접 진입 차단
행동:
- 비공개 트리 또는 비공개 트리의 detail 직접 URL 진입을 시도한다.

기대 결과:
- 접근이 차단된다.
- 빈 화면, 깨진 화면, 무한 로딩 대신 일관된 차단/에러/대체 UI가 나온다.
- 사용자 입장에서 너무 이상한 전환이 아니다.

기록 항목:
- 차단 방식
- 메시지 품질
- 화면 안정성

### STEP 3. 비소유자 로그인 상태 점검
행동:
- 비소유자 계정으로 로그인한 뒤 비공개 트리 접근을 다시 시도한다.

기대 결과:
- 비공개 트리에 접근할 수 없다.
- 소유자 전용 편집 UI나 editor 진입 경로가 잘못 노출되지 않는다.
- 공개 트리만 browse/detail 경로에서 확인 가능하다.

기록 항목:
- 비소유자 접근 결과
- 잘못 노출된 액션 여부

### STEP 4. 소유자 my-trees / editor 접근 확인
행동:
- 소유자 계정으로 로그인하고 `my-trees`와 editor를 연다.

기대 결과:
- 소유자는 자기 공개/비공개 트리를 `my-trees`에서 본다.
- editor에서 공개/비공개 배지와 트리 상태가 자연스럽게 보인다.
- 수정/삭제 등 소유자 전용 액션이 정상적으로 사용 가능하다.

기록 항목:
- 소유자 접근 결과
- 공개/비공개 배지 상태
- 액션 사용 가능 여부

### STEP 5. 공개 트리의 browse/detail 일치 확인
행동:
- 공개 트리 하나를 `my-trees` 또는 editor에서 확인한 뒤, browse/search에서도 찾는다.
- detail로 진입한다.

기대 결과:
- 같은 트리가 browse에 실제로 노출된다.
- browse 카드, preview, detail 정보가 서로 크게 충돌하지 않는다.
- 공개 배지인데 browse에 안 보이거나, browse에 보이는데 detail 진입이 비정상 차단되는 경우가 없어야 한다.

기록 항목:
- browse 노출 여부
- detail 진입 가능 여부
- 상태 일치 여부

### STEP 6. 비공개 트리의 browse 비노출 확인
행동:
- 비공개 트리를 `my-trees` 또는 editor에서 확인한 뒤, browse/search에서 같은 제목/키워드로 찾아본다.

기대 결과:
- 비공개 트리는 browse 카드, preview, 검색 결과에 나타나지 않는다.
- 비공개 상태와 browse 비노출 결과가 일치한다.

기록 항목:
- 비노출 여부
- 검색 누출 여부

### STEP 7. 공개/비공개 전환 후 반영 확인
행동:
- 가능한 경우 트리의 공개 상태를 바꾼다.
- browse/search와 detail 직접 진입에서 결과가 달라지는지 확인한다.

기대 결과:
- 공개로 전환하면 browse에 노출될 수 있어야 한다.
- 비공개로 전환하면 browse에서 사라져야 한다.
- 캐시 때문에 오래된 권한 상태가 장시간 남지 않는다.

기록 항목:
- 전환 전/후 노출 변화
- 반영 지연 여부
- 캐시 혼선 여부

### STEP 8. 트리 공개와 순간 공개 집계 관계 확인
행동:
- 가능하면 공개 트리 안에서 대표 순간/preview 순간/연결된 순간 수가 browse/detail에 어떻게 반영되는지 본다.

기대 결과:
- browse 노출 기준과 detail 표시 기준이 완전히 다른 상태를 말하지 않는다.
- 트리가 공개인데 preview가 전부 빈 상태로만 보이거나, 순간 집계가 이상하게 줄어든 경우는 기록한다.
- 이 단계는 pass/fail보다 체크포인트 기록이 목적이다.

기록 항목:
- 대표 순간/preview 집계 이상 여부
- browse/detail 불일치 여부

---

## 5. 에지 체크

- 공개 트리 안 preview 정보가 빈약해도 browse가 깨지지 않는가
- detail 직접 진입 시 권한 체크가 일관적인가
- 비공개 차단 시 UI가 지나치게 거칠지 않은가
- 공개/비공개 전환 후 캐시가 오래 남아 잘못된 상태를 보여주지 않는가

---

## 6. 최종 판정

통과:
- 공개/비공개와 소유자/비소유자 경계가 browse, detail, editor에서 일관되게 유지된다.

조건부 통과:
- 데이터 누출은 없지만 차단 UX나 캐시 반영이 다소 거칠다.

실패:
- 비공개 트리가 browse에 노출되거나, 비소유자가 접근 가능하거나, 공개 상태와 browse 결과가 명백히 어긋난다.
