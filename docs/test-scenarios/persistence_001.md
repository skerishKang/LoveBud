# PERSISTENCE-001

이 문서는 저장 이후의 일관성과 재진입 안정성을 검증하는 현재 대표 시나리오입니다.

목적은 트리와 순간을 저장한 뒤, 새로고침, 뒤로가기, `my-trees` 복귀, 다시 editor 진입, 필요 시 browse/detail 재확인을 거치는 동안 데이터와 상태 문구가 서로 어긋나지 않는지 확인하는 것입니다.

---

## 1. 왜 중요한가

사용자는 저장 버튼을 눌렀으면 남았다고 믿습니다. UI는 성공처럼 보이는데 실제 저장이 안 되어 있거나, 새로고침 후 사라지거나, `my-trees`, editor, browse, detail이 서로 다른 상태를 말하면 신뢰가 크게 깨집니다.

따라서 이 시나리오는 저장 성공 자체보다 **저장 이후의 상태 일관성**을 검증합니다.

---

## 2. 범위

### 핵심 질문
- 저장 직후 editor에 즉시 반영되는가
- 새로고침 후에도 유지되는가
- `my-trees`와 editor가 같은 상태를 보여주는가
- 뒤로가기와 재진입을 거쳐도 데이터가 남는가
- 공개/비공개 상태가 browse 반영까지 이어지는가
- 저장 후 우측 패널/좌측 요약/캔버스 상태 불일치가 재발하지 않는가

---

## 3. 사전 준비

- 테스트용 트리 1개 이상
- 새로 추가할 순간용 URL 1개 이상
- 가능하면 공개/비공개 상태를 확인할 수 있는 트리 1개
- 결과 폴더 권장 형식: `docs/test-scenarios/results/persistence-001-{group}-YYYY-MM-DD-HHMM/`

---

## 4. 단계

### STEP 1. 기준 상태 기록
행동:
- 현재 트리의 순간 수와 구조를 확인한다.
- 가능하면 현재 선택된 순간과 공개/비공개 상태도 기록한다.

기대 결과:
- 시작 상태를 비교 가능한 수준으로 기록할 수 있다.
- 이후 저장 후 변화와 재진입 결과를 판단할 기준이 마련된다.

기록 항목:
- 시작 순간 수
- 시작 선택 상태
- 공개/비공개 상태

### STEP 2. 새 순간 저장
행동:
- editor에서 새 순간 하나를 추가하고 저장한다.

기대 결과:
- 저장 직후 캔버스에 새 순간이 반영된다.
- 좌측 흐름 요약, 우측 패널, 선택 상태가 저장된 새 상태를 같은 기준으로 설명한다.
- 성공 토스트/상태 문구가 최소한 저장 완료를 이해 가능하게 만든다.

기록 항목:
- 저장 성공 여부
- 즉시 반영 여부
- 상태 일치 여부

### STEP 3. 같은 화면에서 재확인
행동:
- 화면 이동 없이 방금 저장한 순간과 패널 상태를 다시 확인한다.

기대 결과:
- 저장 직후 순간이 사라지지 않는다.
- 중복 생성되지 않는다.
- 우측 패널이 이전 내용이나 empty 상태로 되돌아가지 않는다.

기록 항목:
- 같은 화면 유지 여부
- 중복/누락 여부
- 패널 이상 여부

### STEP 4. 새로고침
행동:
- editor를 새로고침한다.

기대 결과:
- 방금 만든 순간이 유지된다.
- 캐시가 먼저 보이더라도 최종 상태가 맞아야 한다.
- 새로고침 후에도 캔버스/좌측/우측이 서로 다른 상태를 말하지 않는다.

기록 항목:
- 새로고침 후 유지 여부
- 캐시 혼선 여부
- 상태 불일치 여부

### STEP 5. 뒤로가기 / 재진입
행동:
- editor에서 뒤로가기를 하거나 `my-trees`로 복귀한 뒤 같은 트리에 다시 들어간다.

기대 결과:
- `my-trees` 목록과 editor의 상태가 크게 어긋나지 않는다.
- 재진입 후 방금 만든 순간과 선택 상태가 유지된다.
- 재진입 직후 우측 패널이 잘못된 빈 상태나 대기 상태로 나타나지 않는다.

기록 항목:
- 복귀 안정성
- 재진입 후 유지 여부
- 목록/editor 정합성

### STEP 6. 기존 순간 수정 후 재확인
행동:
- 기존 순간 하나의 제목/메모/태그를 수정한 뒤 저장한다.

기대 결과:
- 수정 직후 우측 패널과 현재 선택 정보가 최신 값으로 보인다.
- 새로고침 또는 재진입 후에도 수정 값이 유지된다.
- 수정 후 언어/상태 문구가 이전 값과 섞이지 않는다.

기록 항목:
- 수정 성공 여부
- 재진입 후 수정 유지 여부
- 이상 여부

### STEP 7. 공개/비공개 상태 반영 확인
행동:
- 가능한 경우 트리 공개 상태를 확인하거나 전환한다.
- browse/search와 detail 직접 진입에서 반영 여부를 본다.

기대 결과:
- 공개 상태면 browse에 노출될 수 있어야 한다.
- 비공개 상태면 browse에서 사라져야 한다.
- editor에서 본 상태와 browse/detail 결과가 장시간 어긋나지 않는다.

기록 항목:
- 공개 상태 반영 여부
- browse 노출 여부
- 캐시 지연 여부

### STEP 8. 다른 진입 경로 일관성 확인
행동:
- 가능하면 detail 또는 browse 경유로 같은 순간/트리를 다시 확인한다.

기대 결과:
- editor에서 저장한 데이터가 다른 진입 경로에서도 일관되게 보인다.
- detail만 오래된 데이터를 보거나 browse만 다른 상태를 말하지 않는다.

기록 항목:
- 경로 간 일관성
- 이상 여부

---

## 5. 에지 체크

- 저장 직후 연속 새로고침
- 뒤로가기 후 재진입
- 저장 후 다른 페이지 갔다가 다시 돌아오기
- 공개/비공개 전환 후 browse 반영 지연
- 저장 후 상태 문구가 다시 "첫 순간 대기"나 "0개"로 잘못 돌아가는지 확인

---

## 6. 최종 판정

통과:
- 저장 후 새로고침, 뒤로가기, 재진입, 목록 복귀를 거쳐도 데이터와 상태 문구가 일관된다.
- 공개/비공개 상태가 browse/detail 반영까지 이어진다.

조건부 통과:
- 저장은 유지되지만 순간적인 캐시 혼선이나 반영 지연이 있다.

실패:
- 저장 직후 또는 새로고침 후 데이터가 사라지거나, 페이지마다 서로 다른 상태를 보인다.
- 저장 후 캔버스/좌측/우측 상태 불일치가 재발한다.
