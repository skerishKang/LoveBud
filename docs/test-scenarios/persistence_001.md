# PERSISTENCE-001

이 문서는 저장 이후의 일관성과 재진입 안정성을 검증하는 현재 대표 시나리오입니다.

목적은 트리와 메모리를 저장한 뒤, 새로고침, 뒤로가기, 재진입, 목록 복귀, 다시 editor 진입을 거치는 동안 데이터가 사라지거나 어긋나지 않는지 확인하는 것입니다.

---

## 1. 왜 중요한가

사용자는 저장 버튼을 눌렀으면 남았다고 믿습니다.
UI는 성공처럼 보이는데 실제 저장이 안 되어 있거나, 새로고침 후 사라지거나, 목록과 editor가 다르면 신뢰가 크게 깨집니다.

따라서 이 시나리오는 저장 성공 자체보다도 **저장 이후의 안정성**을 검증합니다.

---

## 2. 범위

핵심 질문:
- 저장 직후 즉시 반영되는가
- 새로고침 후에도 유지되는가
- my-trees와 editor가 같은 상태를 보여주는가
- 뒤로가기와 재진입을 거쳐도 데이터가 남는가
- 캐시와 실제 데이터가 과하게 어긋나지 않는가

---

## 3. 사전 준비

- 테스트용 트리 1개 이상
- 새로 추가할 메모리용 URL 1개 이상
- 결과 폴더 권장 형식: `docs/test-scenarios/results/persistence-001-{group}-YYYY-MM-DD-HHMM/`

---

## 4. 단계

### STEP 1. 기준 상태 확인
행동:
- 현재 트리의 기존 메모리 수와 구조를 확인한다.

확인 포인트:
- 시작 상태를 명확히 알 수 있는가
- 이후 비교가 가능한가

기록 항목:
- 시작 메모리 수
- 시작 구조 요약

### STEP 2. 새 메모리 저장
행동:
- 새 메모리 하나를 추가하고 저장한다.

확인 포인트:
- 저장 직후 UI가 반영되는가
- 성공 피드백이 충분한가

기록 항목:
- 저장 성공 여부
- 즉시 반영 여부

### STEP 3. 같은 화면에서 재확인
행동:
- 화면 이동 없이 방금 저장한 메모리가 남아 있는지 본다.

확인 포인트:
- 저장 직후 다시 사라지지 않는가
- 중복 생성되지 않는가

기록 항목:
- 같은 화면 유지 여부
- 중복/누락 여부

### STEP 4. 새로고침
행동:
- 페이지를 새로고침한다.

확인 포인트:
- 방금 만든 메모리가 남아 있는가
- 캐시된 화면이 먼저 보여도 최종 상태가 맞는가

기록 항목:
- 새로고침 후 유지 여부
- 캐시 혼선 여부

### STEP 5. my-trees로 복귀
행동:
- my-trees로 돌아간다.

확인 포인트:
- 목록에 반영이 되어 있는가
- 트리 요약 정보와 editor 상태가 크게 어긋나지 않는가

기록 항목:
- 목록 반영 여부
- 요약 정보 일관성

### STEP 6. editor 재진입
행동:
- 같은 트리에 다시 들어간다.

확인 포인트:
- 방금 만든 메모리가 그대로 보이는가
- 구조가 깨지지 않는가

기록 항목:
- 재진입 후 유지 여부
- 구조 안정성

### STEP 7. detail 또는 다른 진입 경로 확인
행동:
- 가능하면 detail 또는 browse 경유 진입으로 같은 데이터를 본다.

확인 포인트:
- 다른 진입 경로에서도 데이터가 일관적인가
- editor 전용 상태와 다른 페이지 상태가 크게 어긋나지 않는가

기록 항목:
- 경로 간 일관성
- 이상 여부

---

## 5. 에지 체크

- 저장 직후 연속 새로고침
- 뒤로가기 후 재진입
- 저장 후 다른 페이지 갔다가 다시 돌아오기
- 캐시가 강하게 남아 오래된 상태를 보여주지 않는지 확인

---

## 6. 최종 판정

통과:
- 저장 후 어떤 기본 이동을 하더라도 데이터가 유지되고, 목록과 editor가 일관된다.

조건부 통과:
- 저장은 유지되지만 순간적인 캐시 혼선이나 정보 반영 지연이 있다.

실패:
- 저장 직후 또는 새로고침 후 데이터가 사라지거나, 페이지마다 서로 다른 상태를 보인다.
