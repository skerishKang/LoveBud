# CORE-RETURNING-001

이 문서는 기존 사용자의 재방문 흐름을 검증하는 현재 대표 시나리오입니다.

목적은 이미 트리를 가진 사용자가 my-trees, editor, detail을 오가며 기존 데이터를 확인하고, 새 메모리를 추가하고, 다시 들어와도 상태가 유지되는지 확인하는 것입니다.

---

## 1. 왜 중요한가

첫 사용이 통과해도, 재방문 경험이 불편하면 제품은 오래 살아남기 어렵습니다.
기존 사용자는 다음이 자연스러워야 합니다.

- 내 트리가 바로 보이는지
- 최근 작업을 이어갈 수 있는지
- 기존 메모리와 새 메모리가 함께 잘 보이는지
- 다시 들어왔을 때 상태가 깨지지 않는지

---

## 2. 범위

대상 페이지:
- my-trees
- editor
- detail

핵심 질문:
- 기존 트리 목록이 안정적으로 보이는가
- 원하는 트리를 쉽게 찾을 수 있는가
- 기존 메모리를 확인하는 흐름이 자연스러운가
- 새 메모리 추가 후 상태가 유지되는가

---

## 3. 사전 준비

- 이미 최소 1개 이상의 트리와 메모리를 가진 계정 사용
- 결과 폴더 권장 형식: `docs/test-scenarios/results/core-returning-001-{group}-YYYY-MM-DD-HHMM/`

---

## 4. 단계

### STEP 1. my-trees 진입
행동:
- 로그인 상태에서 my-trees에 진입한다.

확인 포인트:
- 기존 트리 카드가 보이는가
- 빈 상태로 오인되지 않는가
- 다음 행동이 보이는가

기록 항목:
- 로드 안정성
- 트리 식별 용이성
- 첫 인상

### STEP 2. 기존 트리 선택
행동:
- 기존 트리 중 하나를 선택한다.

확인 포인트:
- 원하는 트리를 쉽게 찾을 수 있는가
- editor 또는 의도한 화면으로 자연스럽게 이동하는가

기록 항목:
- 카드 정보 충분성
- 클릭 후 이동 결과

### STEP 3. 기존 메모리 확인
행동:
- editor 또는 detail에서 기존 메모리를 확인한다.

확인 포인트:
- 기존 데이터가 정상 렌더링되는가
- 제목, 썸네일, 태그 등이 어색하지 않은가
- 연결 정보가 이해되는가

기록 항목:
- 렌더링 안정성
- 가독성
- 혼란 포인트

### STEP 4. 새 메모리 추가
행동:
- 기존 트리에 새 메모리를 하나 추가한다.

확인 포인트:
- 기존 트리 맥락에서 메모리 추가가 쉬운가
- 저장 후 결과가 이해되는가
- 기존 구조가 깨지지 않는가

기록 항목:
- 입력 난이도
- 저장 성공 여부
- 추가 후 구조 이해도

### STEP 5. 기존 메모리와 새 메모리 비교
행동:
- 방금 추가한 메모리와 기존 메모리를 각각 본다.

확인 포인트:
- 오래된 데이터와 새 데이터가 함께 일관되게 보이는가
- 한쪽만 이상하거나 누락되지 않는가

기록 항목:
- 일관성 여부
- 데이터 누락 여부

### STEP 6. 재진입 확인
행동:
- my-trees로 돌아갔다가 같은 트리에 다시 들어간다.

확인 포인트:
- 방금 추가한 메모리가 재진입 후에도 남아 있는가
- 목록과 editor의 상태가 어긋나지 않는가

기록 항목:
- 재진입 후 유지 여부
- 목록과 editor 일치 여부

---

## 5. 에지 체크

- 트리가 여러 개일 때 찾기 쉬운가
- 메모리가 많아졌을 때 렌더링이 버거워 보이지 않는가
- 방금 추가한 메모리만 사라지지 않는가

---

## 6. 최종 판정

통과:
- 기존 사용자가 트리를 찾고 새 메모리를 추가하고 재진입 후 유지까지 확인한다.

조건부 통과:
- 완료는 가능하지만 찾기 어렵거나 맥락 이해가 불안정하다.

실패:
- 기존 트리를 찾기 어렵거나, 추가 후 상태가 깨지거나, 재진입 시 데이터가 사라진다.
