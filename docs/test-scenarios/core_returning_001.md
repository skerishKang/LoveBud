# CORE-RETURNING-001

이 문서는 기존 사용자의 재방문 흐름을 검증하는 현재 대표 시나리오입니다.

목적은 이미 트리를 가진 사용자가 `my-trees → editor → detail`을 오가며 기존 데이터를 확인하고, 새 순간을 추가하거나 수정한 뒤 다시 들어와도 상태와 언어가 안정적으로 유지되는지 확인하는 것입니다.

---

## 1. 왜 중요한가

첫 사용이 통과해도 재방문 경험이 불안정하면 제품은 오래 살아남기 어렵습니다. 기존 사용자는 아래가 자연스러워야 합니다.

- 내 트리가 바로 보이는지
- 원하는 트리를 쉽게 찾을 수 있는지
- editor에서 기존 순간과 현재 선택 상태를 바로 이해할 수 있는지
- 수정/추가 후에도 패널과 캔버스 상태가 일관적인지
- 언어 전환 후 주요 UI가 깨지지 않는지
- 재진입 후에도 방금 작업한 상태가 유지되는지

---

## 2. 범위

### 대상 페이지
- my-trees
- editor
- detail

### 핵심 질문
- 기존 트리 목록이 안정적으로 보이는가
- 트리 카드 정보와 진입 흐름이 충분한가
- 기존 순간 렌더링과 현재 선택 상태가 자연스러운가
- 수정/추가 후 `editor` 상태 불일치가 없는가
- 언어 전환 후 본문 UI가 유지되는가
- 재진입 시 최근 작업이 유지되는가

---

## 3. 사전 준비

- 최소 1개 이상의 트리와 2개 이상의 순간을 가진 계정을 사용한다.
- 가능하면 공개 트리 1개, 비공개 트리 1개를 모두 가진 계정이면 더 좋다.
- 결과 폴더 권장 형식: `docs/test-scenarios/results/core-returning-001-{group}-YYYY-MM-DD-HHMM/`

---

## 4. 단계

### STEP 1. my-trees 진입
행동:
- 로그인 상태에서 `my-trees`에 진입한다.

기대 결과:
- 기존 트리 카드가 정상 표시된다.
- 빈 상태나 로딩 상태로 잘못 남지 않는다.
- 최근 수정순/이름순 등 정렬 또는 요약 바가 있다면 상태가 자연스럽다.

기록 항목:
- 로드 안정성
- 트리 식별 용이성
- 첫 인상

### STEP 2. 언어 전환 확인 (my-trees)
행동:
- Shared Header에서 언어를 전환한다.
- `my-trees` 본문 제목, 설명, 카드 메타, 빈 상태/에러 상태 문구를 본다.

기대 결과:
- header만 바뀌고 본문이 남는 부분 번역이 없어야 한다.
- 카드 메타나 버튼이 다른 언어로 섞이지 않는다.
- 전환 후 트리 목록이 사라지거나 초기화되지 않는다.

기록 항목:
- 본문 반영 여부
- 언어 혼합 여부
- 목록 유지 여부

### STEP 3. 기존 트리 선택 후 editor 진입
행동:
- 기존 트리 중 하나를 선택해 editor로 이동한다.

기대 결과:
- 원하는 트리를 찾기 어렵지 않다.
- editor 이동이 자연스럽고, 로그인/권한 지연 때문에 멈추지 않는다.
- 진입 직후 루트/선택 상태가 이해 가능하다.

기록 항목:
- 카드 정보 충분성
- 클릭 후 이동 결과
- 진입 첫 인상

### STEP 4. 기존 순간 렌더링 및 상태 일관성 확인
행동:
- editor에서 기존 순간들을 본다.
- 현재 선택된 순간이 있으면 좌측 상태, 캔버스, 우측 패널을 함께 확인한다.

기대 결과:
- 기존 순간이 정상 렌더링된다.
- 선택된 순간 제목과 우측 패널 내용이 일치한다.
- moment count, 트리 상태 문구, 공개/비공개 배지, 현재 선택 안내가 서로 모순되지 않는다.

기록 항목:
- 렌더링 안정성
- 상태 일치 여부
- 가장 어색한 문구 1개

### STEP 5. 기존 순간 수정
행동:
- 기존 순간 하나를 선택해 제목/감정 메모/감정 태그 중 일부를 수정한다.

기대 결과:
- 수정 진입과 저장이 어렵지 않다.
- 저장 후 우측 패널 내용이 즉시 최신 상태로 바뀐다.
- 수정 전/후 언어가 섞이거나 이전 내용이 남지 않는다.

기록 항목:
- 수정 성공 여부
- 저장 직후 패널 반영 여부
- 이상 여부

### STEP 6. 새 순간 추가
행동:
- 같은 트리에 새 순간 하나를 추가한다.

기대 결과:
- 기존 트리 맥락에서 추가 진입이 쉽다.
- 저장 후 새 순간이 캔버스에 나타난다.
- 좌측 흐름 요약, 우측 패널, 선택 상태가 새 순간 또는 현재 선택 상태를 일관되게 설명한다.

기록 항목:
- 입력 난이도
- 저장 성공 여부
- 추가 후 구조 이해도

### STEP 7. 언어 전환 확인 (editor)
행동:
- editor에서 언어를 다시 전환한다.
- 좌측 흐름 영역, 버튼, 우측 패널 제목/설명, 수정 액션을 확인한다.

기대 결과:
- editor 본문 문구가 함께 바뀐다.
- 상태 문구와 액션 버튼이 다른 언어로 섞이지 않는다.
- 현재 선택 상태와 트리 상태가 리셋되지 않는다.

기록 항목:
- 본문 반영 여부
- 상태 유지 여부
- 레이아웃 이상 여부

### STEP 8. detail 진입 및 복귀
행동:
- editor에서 detail로 이동 가능한 경로를 사용해 기존 또는 방금 추가한 순간을 detail에서 본다.
- 다시 editor 또는 목록으로 돌아온다.

기대 결과:
- detail에서 현재 보고 있는 순간과 트리 맥락이 이해된다.
- 뒤로가기 또는 복귀 후 이전 목록/에디터 흐름이 크게 깨지지 않는다.

기록 항목:
- detail 이해도
- 복귀 안정성
- 탐색 연속성

### STEP 9. my-trees 복귀 후 재진입
행동:
- `my-trees`로 돌아갔다가 같은 트리에 다시 들어간다.

기대 결과:
- 방금 수정/추가한 내용이 유지된다.
- 목록과 editor가 서로 다른 상태를 말하지 않는다.
- 재진입 후 우측 패널이 빈 상태나 대기 상태로 잘못 돌아가지 않는다.

기록 항목:
- 재진입 후 유지 여부
- 목록과 editor 일치 여부
- 최종 판단

---

## 5. 에지 체크

- 트리가 여러 개일 때 찾기 쉬운가
- 순간이 많아도 editor가 지나치게 혼잡하지 않은가
- 수정 직후 이전 값이 잠시 남는 캐시 혼선이 없는가
- 방금 추가한 순간만 사라지지 않는가

---

## 6. 최종 판정

통과:
- 기존 사용자가 트리를 찾고, 수정/추가를 수행하고, 재진입 후에도 같은 상태를 본다.
- 언어 전환 후 `my-trees`, `editor` 본문이 유지된다.

조건부 통과:
- 완료는 가능하지만 찾기 어렵거나 상태/언어 반영이 부분적으로 어색하다.

실패:
- 기존 트리를 찾기 어렵거나, 수정/추가 후 상태가 깨지거나, 재진입 시 데이터가 사라진다.
- 캔버스/좌측/우측이 서로 다른 상태를 말한다.
