# LoveBud CTO MVP 핸드오프

## 1. 현재 읽기

이 폴더는 오래된 `133-relovetree` 프로젝트의 빠른 MVP 브랜치입니다.

이 핸드오프에 사용된 진실의 출처:

- `133-relovetree/docs/product/PRODUCT_IDENTITY.md`
- `133-relovetree/docs/product/MVP_SCOPE.md`
- `133-relovetree/docs/product/USER_FLOW.md`

현재 `LoveBud` 상태:

- 정적 프로토타입 페이지 이미 존재: `index.html`, `editor.html`, `detail.html`, `search.html`, `login.html`
- `css/global.css`에 공유 시각적 톤 존재
- JS는 아직 목데이터 기반
- 일부 페이지/스크립트 계약이 깨져 있어 실제 MVP 반복 전에 정리 필요

이미 발견된 중요한 불일치:

- `editor.html`은 `#canvasArea`와 `#canvasSvg`를 사용
- `js/editor.js`는 `#canvas`와 `#organic-svg`를 찾음
- 결과: 현재 에디터 스크립트가 그대로 렌더링될 수 없음

## 2. LoveBud 1차 MVP 범위

우리는 오래된 제품 전체를 다시 만들고 있지 않습니다.
우리는 하나의 좁은 루프를 검증하고 있습니다:

1. 사용자가 홈페이지에 landing하여 빠르게 제품 이해
2. 사용자가 기록 흐름을 열 수 있음
3. 사용자가 첫 메모리 노드를 생성하거나 시뮬레이션 가능
4. 사용자가 트리처럼 편집기 안에서 해당 메모리를 볼 수 있음
5. 사용자가 하나의 메모리에 대한 상세 페이지를 열 수 있음
6. 사용자가 최소한의 커뮤니티/탐색 페이지를 browse 가능

범위 내 유지:

- 홈
- 로그인 스텁
- 에디터
- 메모리 상세
- 커뮤니티 탐색
- 공유 내비게이션 및 시각 시스템
- 나중에 API 교체 가능할 정도로 강한 목데이터 계약

범위 외 보류:

- 실제 백엔드 통합
- 실제 인증 제공자 연결
- 댓글, 좋아요, 저장 카운트 지속성
- 고급 트리 편집
- 관리자
- 결제
- 전체 설정/마이페이지
- AI 기능

## 3. CTO 위임 규칙

로컬 모델 사용 시, 한 번에 하나의 경계된 작업만 제공합니다.

모든 작업자에게 필수 규칙:

- 제품 정체성을 따뜻한 스크랩북/감정 트리에서 벗어나도록 재디자인하지 말 것
- 프롬프트가 명시적으로 리팩터를 허용하지 않는 한 기존 파일 구조 유지
- 작고 검토 가능한 편집 선호
- 가능한 한 목데이터 중앙 집중화 유지
- 요청하지 않는 한 백엔드 의존성 추가하지 말 것
- 셀렉터, ID, 또는 페이지 계약이 일관되지 않으면, 해킹 계층을 추가하는 대신 계약 수정

## 4. 작업 큐

권장 순서:

1. 깨진 페이지-대-스크립트 계약 수정
2. 공유 목데이터 모델 정규화
3. 첫 메모리 MVP를 위한 에디터 흐름 believable하게 만들기
4. 상세/탐색/내비게이션 일관성 있게 만들기
5. 반응형 패스 조이기
6. 카피 다듬기 및 빈 상태 다듬기
7. 최종 스모크 QA

## 5. 로컬 모델 프롬프트 팩

아래 프롬프트를 그대로 또는 약간 편집하여 사용합니다.

### 프롬프트 1: 계약 수정 작업자

```text
당신은 LoveBud MVP 폴더 내에서만 작업하고 있습니다.

목표:
깨진 DOM/스크립트 계약을 수정하고 기존 모든 페이지가 JS 셀렉터 오류 없이 로드되도록 합니다.

맥락:
- 이것은 오래된 전체 제품이 아닌 가벼운 MVP 브랜치입니다.
- 현재 페이지 세트 유지: index.html, editor.html, detail.html, search.html, login.html
- 백엔드 통합 추가하지 말 것
- 현재 따뜻한 감정 시각 정체성 유지

이미 식별된 문제:
- editor.html은 #canvasArea와 #canvasSvg 사용
- js/editor.js는 #canvas와 #organic-svg를 기대

작업:
1. HTML과 JS 파일에서 셀렉터/ID/클래스 불일치 감사
2. 가장 작은 일관된 편집으로 불일치 수정
3. 각 페이지가 명백한 런타임 오류 없이 초기화되도록 보장
4. 스크립트가 누락된 마크업에 의존할 경우, 누락된 마크업을 추가하거나 계약이 정확하도록 스크립트 단순화

제약:
- 코드 단순하게 유지
- 프레임워크 도입하지 말 것
- 전체 UI 재작성하지 말 것
- 어디에나 방어적 코드 덧대는 것보다 계약 수정 선호

산출물:
- 업데이트된 파일들
- 무엇이 깨졌고 무엇을 수정했는지 짧은 요약
- 의도적으로 건드리지 않은 남은 구조적 문제 목록
```

### 프롬프트 2: 공유 목데이터 작업자

```text
당신은 LoveBud MVP 폴더 내에서만 작업하고 있습니다.

목표:
에디터, 상세, 탐색 전반에 걸쳐 제품이 하나처럼 느껴지도록 하는 하나의 일관된 목데이터 모델 생성.

맥락:
- 현재 JS 파일들은 각각 분리된 하드코딩 목데이터 사용
- 나중에 MVP 백엔드 필드에 매핑되는 하나의 최소 스키마 필요
- 실제 백엔드 통합 없음

대상 최소 스키마:
- tree.id
- tree.title
- tree.visibility
- memory.id
- memory.treeId
- memory.title
- memory.memo
- memory.timestamp
- memory.sourceUrl
- memory.sourceType
- memory.emotionTags
- memory.parentId
- memory.thumbnail
- memory.createdAt

작업:
1. 이 코드베이스에 대해 가능한 가장 간단한 방식으로 공유 목데이터 모듈 추가
2. editor.js, detail.js, search.js를 해당 공유 데이터를 소비하도록 리팩터
3. 페이지 간 링크가 일관된 ID로 동작하도록 보장
4. 목콘텐츠를 Lovetree 정체성에 맞게 감정적으로 유지

제약:
- 빌드 스텝 없음
- 외부 라이브러리 없음
- 파일 수 적게 유지
- 상태 관리 과도하게 설계하지 말 것

산출물:
- 업데이트된 파일들
- 사용된 최종 목 스키마
- 나중에 API 교체가 목 모듈을 어떻게 교체할 수 있는지에 대한 짧은 참고사항
```

### 프롬프트 3: 에디터 MVP 작업자

```text
당신은 LoveBud MVP 폴더 내에서만 작업하고 있습니다.

목표:
현재 에디터 페이지를 정적인 예술 작품 대신 believable 첫 메모리 MVP로 전환.

이 페이지가 증명해야 할 것:
- 첫 메모리가 존재할 수 있음
- 메모리 노드가 트리 경로로 나타날 수 있음
- 노드 선택 시 상세 패널 업데이트됨
- 새로운 목 메모리 추가가 이해 가능, 실제로는 여전히 로컬 전용

작업:
1. 기존 에디터 레이아웃 유지
2. 노드 렌더링 신뢰성 있게 만들기
3. 하나의 최소 "메모리 추가" 상호작용 추가 (로컬/목데이터만 사용)
4. 부모-자식 연결 시각적으로 지원
5. UX 감정적으로 따뜻하게, 대시보드 같지 않게 유지

제약:
- 백엔드 없음
- 모달 프레임워크 없음
- 주요 시각 재디자인 없음
- 상호작용은 단순할 수 있으나 의도적이어야 함

산출물:
- 업데이트된 파일들
- 메모리-추가 상호작용에 대한 짧은 설명
- 범위 MVP 크기로 유지하기 위해 만들어진 타협 목록
```

### 프롬프트 4: 탐색/상세 일관성 작업자

```text
당신은 LoveBud MVP 폴더 내에서만 작업하고 있습니다.

- 실제 댓글이나 반응 지속성 추가하지 말 것

- 업데이트된 파일들
- UX 변경 사항 짧은 목록
```

```text
- 긴 마케팅 단락 추가하지 말 것

- 주요 카피 변경 목록
```


## 6. CTO 검사 목록

다음 조건을 만족할 때만 작업자 산출물을 승인합니다:

- 첫 사용자 루프가 30초 이내에 보임
- 에디터에 더 이상 깨진 셀렉터나 죽은 JS 없음
- 탐색/상세/에디터가 하나의 믿을 만한 데이터 스토리 공유
- 제품이 여전히 감정적이고 따뜻하게 느껴짐
- 페이지들이 연결되지 않은 목업들이 합쳐진 것처럼 보이지 않음
- 모바일에서 핵심 경험이 무너지지 않음

## 7. 다음에 작업자에게 요청할 것

첫 번째 패스가 완료된 후:

1. 인라인 페이지별 스타일을 더 깔끔한 CSS 파일로 추출
2. `localStorage`를 사용하는 하나의 로컬 지속성 레이어 추가
3. 가짜 로그인 토글을 더 명확한 MVP 세션 스텁으로 교체
4. 하나의 가이드된 빈 트리 온보딩 상태 추가
5. 나중에 백엔드 연결을 위한 얇은 API 솔기 준비
