# 신규 사용자 UX 개선 계획 (Hearts2Hearts H2H)

> 기준 테스트: `docs/test-scenarios/results/h2h-newuser-test-2026-04-18-0929/test-result.md`
> 작성일: 2026-04-18
> 상태: 실행 계획

## 목적

신규 사용자가 `홈 -> 회원가입/로그인 -> 내 트리 -> 에디터 -> 첫 기억 추가`까지
큰 혼란 없이 완료하도록 UX를 보정한다.

이 문서는 실제 사용자 테스트에서 드러난 문제를 기준으로,
이미 반영된 수정과 아직 남은 작업을 분리해 정리한다.

## 테스트 핵심 발견

### 1. 홈 진입 목적이 3초 안에 명확하지 않음
- 서비스가 무엇인지, 무엇을 먼저 해야 하는지 바로 이해되지 않음
- `시작하기`와 `둘러보기` 중 어느 행동이 우선인지 잠깐 멈춤

### 2. 회원가입 진입은 가능하지만 "로그인인가 회원가입인가"가 처음엔 헷갈림
- 이메일 시작을 눌렀을 때 로그인 모달이 먼저 보이면 신규 사용자가 멈춤

### 3. 새 트리와 샘플 트리의 구분이 약함
- 사용자는 "새 트리를 만들었다"고 느껴야 하는데,
  초기 상태가 샘플 BTS 트리처럼 보이면 흐름이 끊김

### 4. 첫 기억 추가가 핵심인데, 초기 빈 상태의 행동 유도가 충분히 강하지 않음
- 에디터에 들어온 뒤 무엇을 눌러야 하는지 한 번 더 생각하게 됨

### 5. 저장 후 다음 행동이 약함
- 사용자는 "이제 공유는 어디서 하지?"에서 멈춤
- 공개/비공개 상태와 링크 복사 등 다음 행동이 충분히 드러나야 함

## 현재 반영 상태

### 이미 반영된 항목
- 홈 CTA 우선순위 정리
  - 주 CTA: `나의 첫 러브트리 만들기`
  - 보조 CTA: `예시 트리 먼저 보기`
- 홈 microcopy / 시작 흐름 보강
- 로그인 페이지 `mode=signup` 진입 지원
- 로그인/회원가입 모드 배지 추가
- 새 트리 empty state 강화
  - `🌱 새 트리의 시작`
  - `🎉 첫 번째 순간을 추가해보세요!`
- editor/detail에서 공개/비공개 상태 노출 강화
- editor에서 링크 복사 CTA 추가

## 우선순위별 실행 계획

### P0. 사용자 핵심 루프 안정화

#### P0-1. 노드 추가 실패 재현 여부 재검증
- 대상: `pages/editor.html`, `js/editor.js`
- 이유: 테스트 원문에서는 가장 심각한 blocker였음
- 목표:
  - 현재 코드 기준으로 실제로 재현되는지 먼저 확인
  - 재현되면 즉시 원인 추적
  - 재현되지 않으면 "이전 버전 이슈 또는 환경 이슈"로 문서화

완료 기준:
- 신규 사용자 계정으로 첫 기억 추가가 성공한다
- 버튼 클릭 후 무반응이 없어야 한다

#### P0-2. 새 트리 시작 상태를 더 분명히 유지
- 대상: `js/editor.js`, `pages/editor.html`
- 목표:
  - 샘플 트리와 신규 트리가 시각적으로 섞이지 않게 유지
  - 첫 행동 CTA가 캔버스/패널 양쪽에서 드러나게 유지

완료 기준:
- 신규 트리 진입 시 샘플 아티스트 정보 대신 빈 상태 메시지가 먼저 보인다
- 사용자가 `영상 추가`가 첫 행동임을 바로 이해할 수 있다

### P1. 신규 사용자 진입 UX 정리

#### P1-1. 홈을 "행동 허브"로 유지
- 대상: `index.html`
- 목표:
  - 홈을 브랜드 소개보다 행동 허브로 읽히게 유지
  - 주 CTA와 보조 CTA를 계속 분리

추가 검토 항목:
- Hero 설명 문구가 충분히 명확한가
- 하단 CTA 섹션이 여전히 필요한가
- intro 진입은 보조 링크 수준으로 충분한가

#### P1-2. 회원가입 기본 진입 흐름 고정
- 대상: `pages/login.html`, `js/auth.js`
- 목표:
  - 홈에서 온 신규 사용자는 기본적으로 회원가입 모드로 들어오게 유지
  - 모드 전환의 현재 상태가 눈에 띄게 보이게 유지

완료 기준:
- `?mode=signup` 진입 시 이메일 모달이 자동으로 열림
- 모달 상단에 현재 모드가 보임

### P2. 저장 후 다음 행동 강화

#### P2-1. 공유/공개 상태의 다음 행동 정리
- 대상: `js/editor.js`, `js/detail.js`
- 목표:
  - 공개/비공개 상태를 더 분명하게 읽히게 유지
  - 링크 복사 CTA가 실제 사용 흐름에서 자연스럽게 보이게 유지

추가 검토 항목:
- 링크 복사 토스트가 충분히 명확한가
- 비공개 트리일 때 "왜 공유가 안 되는지" 설명이 필요한가

#### P2-2. my-trees에서 관리 행동 강화
- 대상: `pages/my-trees.html`, `js/my-trees.js`
- 목표:
  - 새 트리 만들기 CTA가 한눈에 보여야 함
  - 추후 편집/삭제/정렬 등 관리 행동의 자리도 고려

참고:
- 테스트 원문에는 `새 트리 만들기 버튼이 잘 안 보였다`는 기록이 있음
- 최근 코드에서 이미 구현됐더라도, 시각적 발견 가능성은 별도 문제임

## 브라우저 검증이 필요한 항목

### 반드시 확인
1. 홈 첫 CTA가 실제로 덜 헷갈리는지
2. `mode=signup` 진입이 자연스러운지
3. 새 트리 생성 후 빈 상태가 샘플처럼 보이지 않는지
4. 첫 기억 추가가 실제로 성공하는지
5. 공개 트리에서 링크 복사가 자연스럽게 이해되는지

### 있으면 좋은 추가 확인
1. 모바일에서 CTA 레이아웃이 어색하지 않은지
2. 비공개 트리 문구가 충분히 이해되는지
3. detail에서 visibility 배지가 시선을 과도하게 뺏지 않는지
