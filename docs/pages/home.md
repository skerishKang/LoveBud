# home (랜딩 / 첫 화면)

## 페이지 목적
처음 방문한 사용자가 LoveBud의 정체성을 빠르게 이해하고, 로그인 또는 서비스 탐색으로 자연스럽게 진입하도록 만드는 진입 페이지.

## 사용자 목표
1. LoveBud가 무엇인지 짧게 파악
2. 감성적 분위기와 핵심 가치 이해
3. 로그인 또는 다음 탐색 행동으로 이동

---

## 현재 구현 상태

### 현재 파일 구조
- `index.html`
- `js/index.js`
- `css/index.css`

### 현재 UI 성격
- 대형 hero 중심 랜딩
- 감성적 색상과 부드러운 장식 요소 사용
- reveal animation, 언어 토글 버튼, 카드형 섹션 포함

### 현재 동작
- `js/index.js`는 스크롤 reveal과 언어 버튼 활성화만 담당
- 언어 전환은 시각 상태만 바뀌고 실제 i18n 연결은 없음
- 홈에서 실제 핵심 루프(`my-trees`, `editor`, `search`)로 이어지는 제품 흐름은 약함

---

## 현재 잘 되는 것

- 첫 화면의 분위기와 톤은 잡혀 있음
- 랜딩 페이지로서 시각적 완성도는 기본 수준 확보
- 간단한 인터랙션은 존재함

---

## 현재 문제 / 리스크

1. 제품 소개 페이지와 실제 MVP 진입 페이지 사이의 연결이 약함
2. CTA가 핵심 사용자 흐름과 강하게 연결되지 않음
3. 언어 토글이 실제 기능이 아니라 기대 불일치 가능성 있음
4. 문서상 핵심 페이지로 다루기엔 현재 정보 구조가 마케팅 랜딩에 치우쳐 있음
5. `docs/pages/` 인덱스에 빠져 있어 세션 복구 시 홈 페이지 논의가 끊기기 쉬움

---

## 상태별 화면

### 기본
- 감성적 hero
- 소개 섹션
- 시각적 카드/갤러리형 구성

### 로그인 전
- 제품 이해와 CTA가 핵심
- 아직 "내 트리 만들기", "둘러보기", "로그인"의 우선순위 구조가 명확하지 않음

### 로그인 후
- 홈이 유지될지, 바로 `my-trees`로 보낼지 정책이 문서화되어 있지 않음

### 에러 / 빈 상태
- 랜딩 페이지 특성상 복잡한 빈 상태는 없음
- 다만 로그인/세션 상태에 따라 분기 정책이 부재

---

## 필요한 결정

1. 홈을 마케팅 랜딩으로 유지할지
2. 아니면 MVP 허브 페이지로 바꿀지
3. 로그인 사용자를 홈에 남길지, `my-trees`로 리다이렉트할지
4. 언어 토글을 실제 i18n에 연결할지 제거할지

---

## 다음 개선 포인트

1. 홈의 역할을 `브랜드 소개` vs `제품 진입 허브` 중 하나로 명확히 결정
2. 핵심 CTA를 `내 트리 시작`, `공개 트리 둘러보기`, `로그인` 기준으로 재구성
3. 로그인 상태 분기 정의
4. 실제 MVP 플로우와 맞는 섹션 순서 재설계
5. 결정이 끝나면 `index.html`, `js/index.js`, `css/index.css`를 함께 개편

---

## 현재 가장 자연스러운 다음 작업

홈페이지를 페이지별 논의 흐름의 다음 주제로 삼는 것이 맞습니다.

이유:
- 기존 핵심 페이지 문서(`my-trees`, `editor`, `search`, `detail`)는 이미 존재
- `../plans/ROADMAP.md`에서도 다음 항목으로 `Home (landing)`이 명시됨
- 세션 기억이 끊긴 상태에서 홈의 역할부터 다시 정하면 이후 페이지 간 연결이 쉬워짐
