# UI_DESIGN_SYSTEM

> **"Digital Scrapbook of Emotions"**  
> 기술적인 도식화(Flowchart)를 철저히 배제하고, 아날로그 다이어리를 꾸미듯 따뜻하고 유기적으로 연결된 감정의 흐름을 시각화한다.

---

## 1. Design Goal

이 문서는 LoveTree/LoveBud 구현팀이 바로 적용할 수 있는 화면 규격 문서다.  
모든 화면은 기능 노출보다 감정 위계를 우선한다.  
구현 전에는 “무엇을 먼저 느끼게 할 것인가”를 먼저 정하고, 구현 중에는 “무엇이 먼저 보이는가”를 계속 검수한다.

---

## 2. UI Principles & Keywords

Lovetree의 디자인은 차가운 IT 관리 도구의 인상을 지우고, 사용자의 소중한 추억을 담는 **따뜻한 일기장**의 감각을 유지해야 한다.

- **Warm**: 난색 계열의 베이지와 뮤트 로즈 컬러를 사용한다.
- **Organic**: 곡선과 나뭇가지 형태의 흐름을 강조한다.
- **Tactile**: 종이와 스크랩북 같은 부드러운 텍스처를 유지한다.
- **Soft**: 은은한 그림자와 큰 라운드값을 기본으로 한다.

---

## 3. Color System

모든 색상은 아래 변수를 기준으로 통일한다.

```css
:root {
  --color-bg-base: #FDFBF7;
  --color-surface: rgba(255, 255, 255, 0.85);
  --color-primary: #C27C7E;
  --color-secondary: #A8A39C;
  --color-text-main: #3E342F;
  --color-text-muted: #8C827A;
}
```

### Rules
- 완전한 흰색 배경(`#FFF`)을 기본값으로 쓰지 않는다.
- 완전한 검정 텍스트(`#000`)를 기본값으로 쓰지 않는다.
- 채도가 높은 원색을 포인트 컬러로 쓰지 않는다.
- 감정 상태 표현도 강한 경고색보다 완충된 웜톤을 우선한다.

---

## 4. Typography System

### Fonts
- Primary: `Outfit`
- Secondary: `Noto Sans KR`

### Rules
- 본문은 line-height 1.4 이상을 유지한다.
- 제목은 감성 톤을 유지하되 과도하게 무겁지 않게 쓴다.
- 메타 텍스트는 제목보다 먼저 읽히지 않게 크기와 대비를 낮춘다.
- placeholder도 본문보다 지나치게 약하거나 차갑게 보이지 않게 조정한다.

---

## 5. Layout System

### Base Rules
- 리스트 및 상세 페이지의 콘텐츠 폭은 최대 `1200px`를 기본으로 한다.
- 모바일 좌우 패딩은 최소 `20px` 이상 확보한다.
- 넓은 화면에서도 콘텐츠를 화면 가장자리에 붙이지 않는다.

### Navigation Rules
- 탐색 페이지(홈, 커뮤니티, 목록)는 상단 수평 GNB를 사용한다.
- 몰입형 편집 페이지(editor)는 사이드바 또는 문맥형 내비게이션을 사용한다.
- 전역 내비게이션은 대표 순간, hero, preview보다 강하게 보이면 안 된다.

## 6. Page Types

### 6.1 Landing Page
**목적**  
제품 정체성을 전달하고 첫 진입 행동을 유도한다.

**먼저 보여야 하는 것**
- hero headline
- 핵심 설명
- 시작 CTA

**약해야 하는 것**
- 세부 기능
- 보조 링크
- 설정성 버튼

**규칙**
- hero headline이 화면의 1순위여야 한다.
- CTA는 hero 설명 바로 아래에 둔다.
- 기능 목록은 hero를 보조하는 수준까지만 허용한다.
- 첫 화면에서 관리성 문구를 쓰지 않는다.

### 6.2 Appreciation Hub Page
**목적**  
공개 트리를 검색 결과가 아니라 감상 허브로 경험하게 만든다.

**먼저 보여야 하는 것**
- 큐레이션 카드
- preview
- 대표 순간
- 이어진 감정

**약해야 하는 것**
- 검색 input
- 필터
- 시스템 상태
- placeholder 수치

**규칙**
- 카드와 preview가 검색보다 먼저 읽혀야 한다.
- 검색은 보조 도구로 배치한다.
- 기본 상태에서도 감상형 문구를 유지한다.
- `0개`, `준비 중`, `없음`은 정적 기본값으로 두지 않는다.

### 6.3 Detail Appreciation Page
**목적**  
하나의 순간과 감정 흐름을 깊게 감상하게 만든다.

**먼저 보여야 하는 것**
- 대표 순간
- 제목
- 메모
- 이어진 경로

**약해야 하는 것**
- 수치
- 기술 메타
- 시스템 액션

**규칙**
- 제목과 대표 장면을 최상단에 둔다.
- 메타 정보는 제목 아래 보조 계층으로 둔다.
- 관련 순간은 추천 목록보다 감정 경로처럼 보여야 한다.
- 메타가 제목보다 먼저 시선을 잡으면 안 된다.

### 6.4 Editor Page
**목적**  
순간 생성과 감정 흐름 편집을 자연스럽게 만든다.

**먼저 보여야 하는 것**
- 현재 트리
- 현재 순간
- 입력 진입점
- 감정 흐름 캔버스

**약해야 하는 것**
- 설정
- 시스템 메시지
- 보조 필드

**규칙**
- 입력 전에도 감정 맥락이 먼저 보여야 한다.
- 폼은 관리툴처럼 보이지 않게 유지한다.
- 첫 순간과 다음 순간의 의미를 문구로 구분한다.
- 현재 지원하지 않는 입력 타입은 지원하는 것처럼 안내하지 않는다.

### 6.5 Management Page
**목적**  
내 트리를 다시 열고 최소한으로 관리하게 만든다.

**먼저 보여야 하는 것**
- 대표 카드
- 트리 제목
- 다시 열기 행동

**약해야 하는 것**
- 삭제
- 수정
- 설정

**규칙**
- 카드가 파일 목록처럼 보이지 않게 한다.
- 관리 액션은 점메뉴나 보조 버튼으로 후순위 배치한다.
- 대표 비주얼이 없는 반복 카드 상태를 기본으로 두지 않는다.

---

## 7. Card Types

### 7.1 Public Tree Card
**사용 위치**  
browse / search hub

**필수 요소**
- 대표 이미지 또는 대표 텍스트 카드
- 트리 제목
- 짧은 감상형 subcopy
- 최소 메타 1~2개

**규칙**
- 카드 첫인상은 대표 순간이어야 한다.
- `0개`, `준비 중`, `태그 없음`을 기본 노출하지 않는다.
- 메타는 한 줄 또는 두 개 이하로 제한한다.
- 카드 hover는 선택 의도만 강화하고 기능성을 과장하지 않는다.

### 7.2 My Tree Card
**사용 위치**  
my-trees

**필수 요소**
- 대표 이미지 또는 대표 텍스트 카드
- 트리 제목
- 순간 수
- 공개/비공개 상태
- 다시 열기 액션

**규칙**
- 수정/삭제는 1차 노출하지 않는다.
- 관리 액션은 점메뉴로 숨긴다.
- 대표 비주얼 우선순위는 아래 순서를 따른다.
  1. 첫 순간 thumbnail
  2. 첫 순간 title/memo 기반 텍스트 카드
  3. 트리 fallback 비주얼

### 7.3 Moment Preview Card
**사용 위치**  
browse preview, detail related path

**필수 요소**
- 순간 이미지 또는 썸네일
- 순간 제목
- 짧은 감정 설명
- 최소 메타

**규칙**
- 영상 카드보다 감정 장면처럼 보여야 한다.
- 설명은 최대 2줄로 제한한다.
- 메타는 제목과 설명보다 약해야 한다.
- preview가 목록처럼 보이면 안 된다.

### 7.4 Text Hero Card
**사용 위치**  
썸네일이 없는 대표 순간

**필수 요소**
- 작은 kicker
- 대표 제목
- 메모 요약 2~3줄

**규칙**
- 정보 카드가 아니라 감정 카드처럼 보이게 한다.
- 배경은 부드러운 톤을 사용한다.
- 제목을 메모보다 먼저 읽히게 한다.
- 메모는 카드 전체를 채우기보다 여운을 남기는 길이로 제한한다.

## 8. Navigation Intensity

### 8.1 Core Navigation
**대상**  
홈, browse, my-trees, editor 진입, detail 진입

**규칙**
- 항상 보이되 과하게 무겁지 않게 유지한다.
- 현재 페이지는 배경과 톤으로만 구분한다.
- navigation이 hero나 대표 순간보다 강하면 안 된다.

### 8.2 Context Navigation
**대상**  
카드 선택, preview 전환, 현재 순간으로 이동, 트리 열기

**규칙**
- 현재 감상 흐름 안에서만 강하게 보여도 된다.
- 본문보다 크거나 화려하면 안 된다.
- 선택 상태는 명확해야 하지만 관리 액션처럼 보이면 안 된다.

### 8.3 Management Navigation
**대상**  
수정, 삭제, 공개 전환, 설정

**규칙**
- 점메뉴 또는 보조 버튼으로 후순위 배치한다.
- 기본 화면의 첫인상을 장악하면 안 된다.
- destructive action은 직접 노출보다 한 단계 뒤에 둔다.

---

## 9. Empty States

### 9.1 Empty State Principle
빈 상태는 “데이터 없음”을 알리는 시스템 패널이 아니라, 다음 감정 행동을 자연스럽게 안내하는 장면이어야 한다.

### 9.2 Rules
- `0개`, `없음`, `준비 중`, `비어 있음`을 단독 문장으로 쓰지 않는다.
- 제목은 감정 행동 중심으로 쓴다.
- 설명은 1~2문장으로 짧게 유지한다.
- CTA는 하나만 둔다.
- 아이콘은 부드러운 감정 톤을 사용한다.

### 9.3 Writing Pattern
**좋은 예**
- `이 장면에서 러브트리가 시작돼요`
- `대표 순간과 이어진 감정이 이곳에 놓여요`
- `첫 순간을 심으면 흐름이 천천히 자라납니다`

**피해야 할 예**
- `데이터가 없습니다`
- `0개의 항목`
- `업데이트 정보 준비 중`
- `태그 없음`

## 10. Editor States

### 10.1 No Tree Selected
**보여야 하는 것**
- 현재 맥락 설명
- 다음 행동 CTA

**약해야 하는 것**
- 빈 폼
- 기술 라벨

**규칙**
- CTA는 하나만 노출한다.
- 빈 상태도 감정 문맥 안에서 설명한다.

### 10.2 First Moment Creation
**보여야 하는 것**
- 첫 순간이라는 의미
- 링크로 시작 / 텍스트로 시작
- 제목과 메모

**약해야 하는 것**
- 부가 설정
- 태그
- 기술 정보

**규칙**
- 입력 방식은 바로 이해돼야 한다.
- 현재 지원 범위를 넘는 표현을 쓰지 않는다.
- YouTube 링크만 지원하면 그렇게 명시한다.
- 링크가 없어도 텍스트-only 저장 가능하면 분명히 적는다.

### 10.3 Next Moment Creation
**보여야 하는 것**
- 현재 순간에서 이어진다는 맥락
- 다음 감정을 적는 필드

**약해야 하는 것**
- 새 트리 생성 흐름
- unrelated CTA

**규칙**
- “무엇이 이어지는가”가 먼저 보여야 한다.
- 이전 순간과의 연결감을 문구로 보조한다.

### 10.4 Selected Moment View
**보여야 하는 것**
- 현재 순간
- 제목
- 메모
- 핵심 액션 1~2개

**약해야 하는 것**
- 버튼 군집
- 시스템 상태 문구

**규칙**
- 현재 순간이 패널의 1순위여야 한다.
- 메타보다 제목과 메모가 먼저 읽혀야 한다.

### 10.5 Edit State
**보여야 하는 것**
- 현재 수정 중인 내용
- 저장
- 취소

**약해야 하는 것**
- 읽기 모드 장식 요소
- unrelated CTA

**규칙**
- 수정 상태는 명확하게 구분한다.
- 하지만 과도한 폼툴 분위기는 피한다.
- 저장 CTA는 의미형 문구를 우선한다.

## 11. CTA Placement

### 11.1 Primary CTA
**규칙**
- 한 화면에 강한 primary CTA는 1개만 둔다.
- hero 또는 empty state 바로 아래에 둔다.
- 본문을 끊지 않는 위치에 둔다.

### 11.2 Secondary CTA
**규칙**
- primary CTA 옆 또는 아래에 둔다.
- 시각 강도는 primary보다 확실히 약하게 유지한다.

### 11.3 Destructive CTA
**규칙**
- 삭제, 초기화, 영구 전환은 카드 기본면에 두지 않는다.
- 점메뉴 또는 확인 단계 뒤에 둔다.

### 11.4 Browse CTA
**규칙**
- 검색보다 카드 선택이 먼저 행동으로 읽혀야 한다.
- preview에서 detail로 가는 CTA는 감상 흐름 안에 둔다.
- CTA가 필터보다 먼저 눈에 들어오게 한다.

### 11.5 Editor CTA
**규칙**
- 첫 순간 저장 CTA는 입력 흐름의 마지막에 둔다.
- `저장`보다 `첫 순간 심기`, `이 순간 이어가기` 같은 의미형 문구를 우선한다.
- 링크 모드와 텍스트 모드는 문구가 다르게 읽혀도 된다.

## 12. Typography Hierarchy

### 12.1 H1
**사용 위치**  
landing hero, browse hero, detail 대표 제목

**규칙**
- 한 페이지에 1개만 둔다.
- 감정 정체성을 가장 먼저 전달하는 문장에 사용한다.

### 12.2 H2
**사용 위치**  
섹션 제목, page major section

**규칙**
- card title보다 확실히 커야 한다.
- 기능 설명보다 감정 문장을 우선 배치한다.

### 12.3 H3 / Card Title
**사용 위치**  
카드 제목, preview 제목, editor 현재 순간 제목

**규칙**
- 메타보다 확실히 강해야 한다.
- 2줄 이내를 기본으로 한다.

### 12.4 Body Primary
**사용 위치**  
메모, 설명 문단, hero 설명

**규칙**
- line-height를 충분히 확보한다.
- 지나치게 작은 크기를 기본값으로 쓰지 않는다.

### 12.5 Body Secondary
**사용 위치**  
보조 설명, 상태 안내, preview hint

**규칙**
- 제목보다 약하지만 placeholder처럼 보이면 안 된다.
- 문장은 짧고 명확하게 유지한다.
- 색만 흐리게 처리하고 문장을 방치하지 않는다.

### 12.6 Meta / Label
**사용 위치**  
날짜, 공개 상태, 개수, 태그 레이블

**규칙**
- 본문이나 제목보다 먼저 읽히면 안 된다.
- all caps, 과한 대비, 강한 배지를 남용하지 않는다.
- 메타는 감상 흐름을 보조할 때만 노출한다.

## 13. Component Rules

| 요소 | 기본 가이드라인 | 구현 규격 |
| :--- | :--- | :--- |
| **Card** | 둥근 모서리와 은은한 그림자를 유지한다. | `radius: 16px~24px`, `shadow: 0 8px 24px rgba(0,0,0,0.06)` |
| **Button** | 알약 형태의 완전한 곡선을 유지한다. | `radius: 9999px`, `padding: 12px 24px` |
| **Tag** | 부드러운 캡슐 형태를 사용한다. | `height: 28px~32px`, `bg-opacity: 10%` |
| **Thumbnail** | 기본 16:9 비율을 유지한다. | `radius: 8px`, `object-fit: cover` |

### Tree Connection Rules
- 노드를 잇는 선은 항상 유기적인 곡선으로 표현한다.
- 선 두께는 `1.5px ~ 2px` 범위에서 유지한다.
- 직각이나 날카로운 꺾임은 허용하지 않는다.
- 연결선은 기계적 다이어그램보다 감정의 흐름처럼 보여야 한다.

## 14. Prohibitions

1. 순수 블랙(`#000`)과 화이트(`#FFF`) 배경을 기본값으로 사용하지 않는다.
2. 날카로운 직각 모서리(`radius: 0`)를 기본값으로 사용하지 않는다.
3. 플로우차트 스타일의 직선/직각 연결선을 사용하지 않는다.
4. 빽빽하고 차가운 IT 관리자형 레이아웃을 기본 구조로 쓰지 않는다.
5. 형광색이나 채도가 높은 원색을 포인트로 사용하지 않는다.
6. 따뜻한 커스텀 스타일이 없는 기본 브라우저 input을 그대로 노출하지 않는다.
7. 빈 상태에 차가운 시스템 에러 문구를 그대로 쓰지 않는다.
8. 단순 텍스트 리스트를 기본 카드 대체물로 쓰지 않는다.
9. 과도하게 두꺼운 폰트 웨이트를 남용하지 않는다.
10. 모바일에서 요소를 화면 가장자리에 붙이지 않는다.

## 15. Implementation Checklist

### 15.1 Page Structure
- [ ] 이 페이지의 1차 목적이 명확한가
- [ ] 먼저 느껴야 하는 감정이 정의되어 있는가
- [ ] 가장 먼저 보여야 하는 요소가 실제로 첫 시선에 들어오는가

### 15.2 Copy
- [ ] placeholder가 시스템 문구처럼 보이지 않는가
- [ ] `0개`, `준비 중`, `없음`을 정적 기본값으로 두지 않았는가
- [ ] 감상형 문구가 기능형 문구보다 앞서는가
- [ ] 현재 실제 지원 계약을 넘는 표현을 쓰지 않았는가

### 15.3 Layout
- [ ] 카드, preview, hero가 검색이나 필터보다 먼저 읽히는가
- [ ] 관리 버튼이 대표 콘텐츠보다 강하지 않은가
- [ ] destructive action이 후순위 배치되어 있는가

### 15.4 Cards
- [ ] 대표 카드에 실제 감정 단위가 반영되는가
- [ ] 대표 비주얼 우선순위가 정의되어 있는가
- [ ] 썸네일이 없을 때 fallback이 관리형 placeholder가 아닌가

### 15.5 Empty States
- [ ] empty state 제목이 감정 행동 중심인가
- [ ] 설명이 짧고 자연스러운가
- [ ] CTA가 하나로 정리되어 있는가

### 15.6 Editor
- [ ] 첫 순간/다음 순간 문맥이 구분되는가
- [ ] 입력 방식이 현재 지원 범위와 일치하는가
- [ ] URL, 제목, 메모의 위계가 적절한가

- [ ] 관리툴처럼 보이지 않는가
