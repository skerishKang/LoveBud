# Contract: LoveBud Appreciation Order Definition (#3061)
v20260702-guided-path-architecture-1

## 1. 목적 및 배경
트리의 규모가 커지고 노드 간 연결이 복잡해짐에 따라(예: 한 노드에서 4~8개의 분기가 뻗어나가는 경우), 사용자는 어떤 순서로 순간(Moment)들을 감상해야 할지 혼란을 느끼게 된다. 시각적인 연결선(Topology)만으로는 주인이 의도한 서사적 흐름을 완전히 전달하기 어렵다.

본 계약은 시각적 배치와는 독립적으로, 주인이 직접 지정하는 **'의도된 감상 순서(Appreciation Order)'**를 정의하고 이를 시스템에 반영하여, 뷰어가 복잡한 구조 속에서도 길을 잃지 않고 스토리라인을 따라갈 수 있도록 하는 것을 목적으로 한다.

---

## 2. 범위 (Scope)
- **대상 데이터**: 노드들의 정렬 순서를 담은 시퀀스 리스트 (`appreciation_order`).
- **제어 권한**: 트리의 주인(Owner)만이 순서를 정의, 수정, 삭제할 수 있다.
- **적용 대상**: 
  - Owner Editor: 감상 순서를 설정하는 UI 및 데이터 저장.
  - Viewer: 지정된 순서에 따라 노드를 하이라이트하고 '다음' 가이드를 제공.

---

## 3. 데이터 모델 (Data Model)

### 3.1 서버 저장 구조 (Neon/DB)
감상 순서는 `tree_appreciation_orders` (가칭) 테이블 또는 트리의 메타데이터 필드에 저장된다.

| 필드명 | 타입 | 설명 | 비고 |
| :--- | :--- | :--- | :--- |
| `tree_id` | UUID (PK) | 트리의 고유 식별자 | 1:1 관계 |
| `ordered_ids` | JSONB (Array) | `["memId_1", "memId_2", "memId_3", ...]` | 감상 순서대로 나열된 ID 리스트 |
| `updated_at` | Timestamp | 마지막 수정 일시 | 버전 관리용 |

### 3.2 로직 계층 (Logic Layer)
시스템은 다음과 같은 우선순위로 감상 순서를 결정한다.

1. **Explicit Order (명시적 순서)**: `ordered_ids` 리스트가 존재하면 이 순서를 절대적으로 따른다.
2. **Natural Order (자연적 순서)**: 명시적 순서가 없는 경우, 노드 생성 시간(created_at) 또는 트리 구조의 depth-first 탐색 순서를 기본값으로 사용한다.

---

## 4. 핵심 동작 규칙 (Core Rules)

### 4.1 Sequence vs Topology (순서 vs 연결)
- **독립성**: 감상 순서는 노드 간의 물리적 연결선(Edge)과 독립적이다. 연결선이 없더라도 순서상 다음에 위치한다면 가이드 대상이 될 수 있다.
| **시퀀스 우선** | 연결선 기반의 탐색보다 `appreciation_order`에 정의된 시퀀스를 우선하여 타겟 노드를 결정한다.

### 4.2 복잡한 분기(Hub Node) 처리
- **가이드라인 제공**: 8개 이상의 분기가 있는 허브 노드에 도달했을 때, 뷰어는 `appreciation_order` 상의 다음 노드를 특별한 시각적 효과(예: 강조 색상, 애니메이션)로 표시하여 사용자의 시선을 유도한다.
- **분기 탐색**: 사용자가 가이드라인을 무시하고 다른 연결된 노드를 클릭할 경우, 해당 지점부터 다시 가장 가까운 `appreciation_order` 상의 위치를 찾아 연결하거나, 자유 탐색 모드로 전환한다.

### 4.3 편집 규칙 (Editing Rules)
- **Drag-and-Drop**: 주인은 리스트 형태로 나열된 노드들을 드래그 앤 드롭하여 순서를 쉽게 변경할 수 있다.
- **Partial Order**: 전체 노드가 아닌, 특정 핵심 경로(Main Path)만 지정할 수 있으며, 지정되지 않은 노드는 기본 자연 순서에 따라 배치된다.

---

## 5. 수락 기준 (Acceptance Criteria)

- [ ] **순서 지정 및 저장**: 주인이 노드 순서를 변경하고 저장했을 때, 서버에 정확한 ID 시퀀스가 기록되어야 함.
- [ ] **가이드 동작**: 뷰어에서 '다음' 버튼 클릭 시, 연결선 방향과 무관하게 `appreciation_order`에 정의된 다음 노드로 포커스가 이동해야 함.
- [ ] **허브 노드 시각화**: 다중 분기 지점에서 주인 이 정의한 '다음 순서' 노드가 시각적으로 명확하게 강조되어야 함.
- [ ] **Fallback 작동**: 순서가 정의되지 않은 트리에서는 기존의 자연적 탐색 흐름이 그대로 유지되어야 함.

---

## 6. 비목표 (Non-goals)
- **자동 순서 추천**: AI가 자동으로 최적의 감상 순서를 제안하는 기능은 본 계약 범위 외이며, 추후 Scout AI 연동 시 검토한다.
- **다중 경로 지원**: 하나의 트리에 여러 개의 서로 다른 감상 경로(Scenario A, Scenario B)를 만드는 기능은 포함하지 않는다. (단일 메인 경로만 지원)
