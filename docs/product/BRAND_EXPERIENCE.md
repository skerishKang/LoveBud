# BRAND_EXPERIENCE

LoveTree / LoveBud의 브랜드 감성, UX 톤앤매너, 페이지별 표현 원칙을 정리한 문서입니다.

이 문서는 단순한 브랜딩 메모가 아니라, 여러 에이전트와 작업자가 **UI/UX 판단을 할 때 공통으로 따라야 하는 실행 기준**입니다.

---

## 1. 문서 목적

LoveTree는 일반 생산성 툴이나 데이터 정리 앱이 아닙니다.

이 서비스는 팬이 좋아하는 대상과 맺는 감정의 흐름을 기록하고, 감상하고, 나무처럼 키워가는 경험을 제공해야 합니다.

따라서 이 문서는 아래 판단을 위해 존재합니다.

- 이 UI가 팬 경험에 맞는가?
- 이 표현이 너무 차갑거나 기계적으로 느껴지지 않는가?
- 이 페이지가 단순 기능 화면이 아니라 감정 흐름의 장면처럼 느껴지는가?
- 이 기능이 "기록"을 넘어서 "감상"과 "성장"의 경험을 주는가?

---

## 2. 핵심 사용자층

우선 고려 대상은 다음 사용자층입니다.

- **주 사용자층**: 10~20대 여성 팬
- **확장 사용자층**: 30~40대 여성 팬, 일부 남성 팬

중요:
- LoveTree는 특정 성별만을 위한 제품으로 좁게 설계하지 않습니다.
- 다만 **감성적이고 발랄하며 부드러운 인상**을 우선할 때, 주 사용자층과의 감도 정합성이 높다고 봅니다.

즉, 제품은 배타적이지 않되 **팬 감정 경험에 민감한 사용자층의 감도**를 우선 참고합니다.

---

## 3. 브랜드 성격

LoveTree의 핵심 성격은 아래 조합으로 이해합니다.

- 팬페이지 기반 감정 서비스
- 따뜻한 디지털 스크랩북
- 입덕의 첫 순간을 소중히 다루는 공간
- 감정이 이어진 경로를 나무처럼 키워가는 경험
- 나만의 기록에서 시작해, 타인의 트리를 감상하는 공간까지 확장되는 서비스

LoveTree는 다음과 같은 인상을 주면 안 됩니다.

- 관리자 대시보드
- 일반 북마크 정리 툴
- 기계적인 플로우차트 편집기
- 차가운 데이터 관리 시스템
- 범용 커뮤니티 피드

## 4. 톤앤매너 원칙

### 우선해야 하는 인상

- 감성적
- 발랄함
- 부드러움
- 따뜻함
- 조용한 몰입감
- 팬심을 존중하는 관람성

### 피해야 하는 인상

- 차갑고 딱딱함
- 업무 툴 같은 느낌
- 과도한 관리 화면 느낌
- 기계적인 워크플로우 느낌
- 과도하게 기술적인 라벨과 용어

### 표현 기준

좋은 표현 예시:
- 순간 이어가기
- 대표 순간
- 이어진 기억
- 감정 흐름
- 나무가 자라나는 경험
- 이 트리의 시작 순간
- 공개 러브트리 감상

피해야 할 표현 예시:
- 노드 생성
- 워크플로우 관리
- 오브젝트 추가
- 구조 관리
- 관리자 설정
- 엔티티 편집

## 5. 페이지 유형별 UX 원칙

### 5.1 랜딩 페이지

#### 1차 목적
사용자가 LoveTree를 기록 도구가 아니라 감정 기반 러브트리 서비스로 이해하게 만든다.

#### 먼저 느껴야 하는 감정
- 설렘
- 부드러운 초대
- 나만의 감정을 남겨도 된다는 안전감

#### 먼저 보여야 하는 요소
- 제품의 한 줄 정체성
- 러브트리의 의미를 설명하는 hero 문장
- “첫 순간을 심는다”는 핵심 개념
- 시작 CTA

#### 배제 및 이관 대상 (quiet mode 기준)
- 기능 목록 (`pages/intro.html` 또는 행동 직전 화면으로 이관)
- 긴 설명 문단 (`pages/intro.html` 또는 행동 직전 화면으로 이관)

#### 약해야 하는 요소
- 세부 설정
- 보조 링크 군집

#### 금지 패턴
- SaaS 랜딩처럼 보이는 기능 비교 구조
- KPI, 수치, 기능 블록이 hero보다 먼저 읽히는 배치
- “기록 관리”, “데이터 정리” 같은 관리형 문구
- CTA보다 기능 설명이 먼저 시선을 잡는 구조

#### 홈 설명 밀도 운영 기준

LoveTree 홈은 기본적으로 **quiet mode**를 지향합니다.

quiet mode와 explain mode는 서로 다른 제품이 아니라, **같은 정체성을 유지한 채 설명 밀도만 다르게 운용하는 상태 차이**입니다.

- quiet mode는 감정 유입과 첫 행동 유도를 위한 **낮은 설명 밀도 상태**다.
- explain mode는 제품 이해를 돕는 **설명 밀도 상태**다.
- quiet 상태의 홈에서는 **키커, 헤드라인, 짧은 보조문장, CTA 2개, 대표 비주얼**만 남기는 것을 원칙으로 한다.
- explain 상태에서도 홈을 긴 설명서처럼 만들지 않는다.
- 자세한 설명은 홈 안에서 계속 늘리지 말고, `intro` 또는 행동 직전 화면으로 보낸다.

현재 운영 기준에서 `pages/intro.html`은 explain mode의 메인 설명 페이지 역할을 맡는다.

`quiet/home.html`은 운영 페이지가 아니라 **실험 시안**으로 본다.

나중에 홈 quiet/explain 전환을 구현할 경우, 별도 제품 분기보다 **단일 홈 안의 밀도 토글**을 우선 검토한다.

예시:
- `data-home-density="quiet"`
- `data-home-density="explain"`

### 5.2 공개 러브트리 감상 페이지

#### 1차 목적
공개 러브트리를 검색 결과처럼 소비하게 하지 않고, 감상 허브처럼 경험하게 만든다.

#### 먼저 느껴야 하는 감정
- 조용한 호기심
- 다른 사람의 첫 순간을 들여다보는 감상감
- 천천히 고르고 열어보는 몰입감

#### 먼저 보여야 하는 요소
- 최신 또는 큐레이션된 공개 트리 카드
- 대표 순간 또는 시작 순간 preview
- 이어진 감정의 흐름
- 감상 허브라는 문맥을 설명하는 짧은 안내

#### 약해야 하는 요소
- 검색 input의 존재감
- 필터 칩의 강도
- 수치형 placeholder
- 시스템 레이블과 상태 문구

#### 금지 패턴
- 게시판 목록처럼 보이는 카드 구조
- `0개`, `준비 중`, `태그 없음` 같은 시스템 기본 노출
- 검색 input이 화면의 1순위가 되는 배치
- 데이터가 없을 때 빈 관리 패널처럼 보이는 preview
- 카드보다 필터나 정렬이 먼저 눈에 들어오는 구조

### 5.3 공개 러브트리 상세 페이지

#### 1차 목적
하나의 대표 순간과 그 주변 감정 흐름을 깊게 감상하게 만든다.

#### 먼저 느껴야 하는 감정
- 몰입
- 집중
- 감정의 여운

#### 먼저 보여야 하는 요소
- 대표 순간
- 제목
- 메모 또는 감정 설명
- 이어진 순간 경로
- 감정 태그 또는 정서적 맥락

#### 약해야 하는 요소
- 기술적 메타데이터
- 시스템성 보조 버튼
- 탐색보다 관리로 읽히는 액션

#### 금지 패턴
- 영상 상세정보 페이지처럼 보이는 구조
- 메타데이터가 제목보다 먼저 읽히는 배치
- 관련 순간이 추천 목록처럼만 보이는 구성
- 감정보다 기능 설명이 먼저 오는 문장
- 대표 순간보다 하위 카드가 더 강하게 보이는 배치

### 5.4 내 트리 페이지

#### 1차 목적
사용자가 자신이 만든 러브트리를 관리 대상으로만 보지 않고, 감정 단위로 다시 바라보게 만든다.

#### 먼저 느껴야 하는 감정
- 애착
- 소유감
- 다시 열어보고 싶은 감상감

#### 먼저 보여야 하는 요소
- 각 트리의 대표 순간 또는 대표 카드
- 트리 제목
- 최소 메타
- 트리를 다시 여는 행동

#### 약해야 하는 요소
- 수정/삭제 버튼의 직접 노출
- 관리형 숫자 요약
- 시스템 액션 군집

#### 금지 패턴
- 파일 관리자처럼 보이는 리스트
- 수정/삭제가 카드보다 먼저 보이는 구조
- 대표 이미지 없이 동일 카드가 반복되는 상태
- “항목 관리” 중심 문구
- 카드보다 메뉴 버튼이 먼저 눈에 들어오는 배치

### 5.5 내 트리 편집 페이지

#### 1차 목적
사용자가 순간을 입력하는 것이 아니라, 감정의 시작점을 심고 흐름을 이어 간다는 감각으로 편집하게 만든다.

#### 먼저 느껴야 하는 감정
- 조용한 집중
- 감정 정리의 몰입감
- 나만의 트리를 자라게 하는 감각

#### 먼저 보여야 하는 요소
- 현재 트리
- 현재 순간
- 첫 순간 또는 다음 순간을 남기는 입력 진입점
- 캔버스 위 감정 흐름

#### 약해야 하는 요소
- 폼 필드의 관리형 분위기
- 기술적 라벨
- 과한 상태 메시지
- 불필요한 보조 버튼

#### 금지 패턴
- 일반 CMS처럼 보이는 입력 우선 구조
- URL, 태그, 설정이 제목과 메모보다 먼저 보이는 흐름
- 입력 필드만 남고 감정 맥락이 사라지는 배치
- 지원하지 않는 기능을 지원하는 것처럼 읽히는 안내 문구
- placeholder가 제품 톤과 분리되는 상태

### 5.6 로그인 / 시작 플로우

#### 1차 목적
로그인과 시작을 기능 장벽이 아니라 내 러브트리를 시작하는 진입으로 느끼게 만든다.

#### 먼저 느껴야 하는 감정
- 부담 없음
- 시작의 기대감
- 자연스러운 진입감

#### 먼저 보여야 하는 요소
- 왜 시작하는지 설명하는 문장
- 로그인 이후 생기는 변화
- 명확한 시작 CTA

#### 약해야 하는 요소
- 시스템 메시지 톤
- 에러 중심 안내
- 기술적 설명

#### 금지 패턴
- 로그인 화면이 차가운 게이트처럼 보이는 구조
- 시작 이유보다 인증 절차가 먼저 보이는 배치
- 감정 서비스와 분리된 일반 계정 화면 같은 인상

### 5.7 Settings / Account

#### 1차 목적
계정과 환경을 조정하되, 전체 감상 경험을 깨지 않는 보조 화면으로 유지한다.

#### 먼저 느껴야 하는 감정
- 안정감
- 명확함
- 부담 없음

#### 먼저 보여야 하는 요소
- 현재 계정 상태
- 필요한 설정 항목
- 명확한 저장/변경 액션

#### 약해야 하는 요소
- 장식적 감성 표현
- 과한 hero
- 감상 문맥을 흉내 내는 연출

#### 금지 패턴
- 감상 허브와 동일한 위계를 쓰는 구조
- 설정 항목보다 장식이 먼저 보이는 배치
- 중요하지 않은 옵션이 상단을 차지하는 구성
- 설정 화면에서 감정 CTA를 강하게 노출하는 방식

## 6. Cross-page Emotional Hierarchy

모든 페이지는 아래 위계를 기본으로 삼는다.

1. 감정 단위: 대표 순간, 첫 순간, 이어진 감정
2. 감상 단위: 제목, 메모, 대표 카드, preview
3. 선택 단위: 현재 트리, 현재 순간, 선택된 카드
4. 보조 단위: 공개 여부, 날짜, 개수, 태그
5. 시스템 단위: 설정, 관리, 기술 상태, placeholder

상위 단위가 하위 단위보다 먼저 읽혀야 한다.  
하위 단위가 상위 단위를 가리거나 첫인상을 장악하면 브랜드 경험이 깨진다.

## 7. UI 컴포넌트 원칙

### 버튼
- 기능 버튼이라도 툴 버튼처럼 딱딱하게 보이지 않게 한다.
- 주 CTA와 보조 CTA의 계층을 명확히 구분한다.
- 동일 목적의 버튼을 중복 배치하지 않는다.
- 몰입을 깨는 전역 버튼은 상단이나 약한 위치로 보낸다.

### 카드
- 카드가 placeholder처럼 보이면 안 된다.
- 감상 카드와 편집 카드의 목적을 구분한다.
- 카드 내부는 정보량보다 읽히는 계층을 먼저 설계한다.

### 패널
- 오른쪽 패널은 정보 덤프가 아니라 현재 문맥 설명 역할을 해야 한다.
- 현재 선택 대상과 가능한 행동이 한눈에 보여야 한다.

### 노드 / 트리 캔버스
- 노드는 단순 썸네일 카드가 아니라 감정의 장면이어야 한다.
- 첫 노드, 대표 노드, 선택된 노드의 상태 차이를 보여야 한다.
- 다음 순간을 이어갈 수 있다는 affordance가 필요하다.
- 연결선은 기계적 다이어그램보다 유기적 흐름에 가깝게 보여야 한다.

## 8. 카피 원칙

### 선호하는 방향
- 감정 중심
- 장면 중심
- 흐름 중심
- 부드러운 안내
- 팬 경험에 맞는 표현

### 피해야 하는 방향
- 지나치게 기술적 표현
- 관리자/설정 중심 표현
- 차갑고 무미건조한 시스템 문장
- 기능은 맞지만 감정선이 없는 문장

### 카피 체크리스트
1. 이 문장이 너무 툴처럼 들리지 않는가?
2. 팬 감정 경험과 어울리는가?
3. 감상, 성장, 연결의 느낌이 남아 있는가?
4. 현재 지원하지 않는 기능을 지원하는 것처럼 들리지 않는가?

---

## 9. 인터랙션 원칙

- 사용자는 다음 행동을 추론하지 않게 한다.
- 다음 행동은 시각적으로 드러나야 한다.
- 하지만 그 표현이 기계적 편집 툴처럼 보여서는 안 된다.
- 몰입이 중요한 페이지에서는 중간에 전역 이동을 강하게 노출하지 않는다.
- 첫 상태, 빈 상태, 노드 하나뿐인 상태를 따로 설계한다.
- 저장, 추가, 수정 후에는 감정 흐름이 이어졌다는 피드백이 필요하다.

---

## 10. 에이전트 작업 체크리스트

에이전트가 UI/UX 작업을 제안하거나 수정할 때는 아래를 확인한다.

1. 이 화면이 팬페이지 기반 감성 서비스로 느껴지는가?
2. 생산성 툴처럼 차갑게 보이지 않는가?
3. 랜딩, 감상, 편집 페이지의 역할 차이가 살아 있는가?
4. 카피가 툴 중심 용어에 치우치지 않았는가?
5. 감정 흐름과 성장 경험이 전달되는가?
6. affordance는 충분하지만 기계적인 워크플로우 UI를 그대로 가져오지 않았는가?
7. 중복 CTA, 어색한 전역 버튼, 의미 불분명한 레이블이 없는가?

---

## 11. 적용 우선순위

UI 관련 판단이 필요할 때는 아래 우선순위를 따른다.

1. 제품 정체성과 팬 경험에 맞는가
2. 현재 페이지의 역할이 명확한가
3. 사용자가 다음 행동을 쉽게 이해하는가
4. 기능보다 감정 흐름이 먼저 읽히는가
5. 구현 복잡도보다 제품 인상 훼손이 더 큰 문제는 아닌가
