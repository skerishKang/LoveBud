# UI_COPY_DIET_GUIDE

LoveBud / LoveTree 전역 UI 카피 다이어트 기준입니다.

목표는 하나입니다.

- **설명을 줄이고, 콘텐츠와 행동을 앞으로 당긴다.**

이 문서는 페이지별 땜질 기준이 아니라, 앞으로 홈/둘러보기/내 트리/소개/상세 전반에 공통 적용할 **운영 규칙**입니다.

---

## 1. 왜 필요한가

현재 main 기준 화면들은 전반적으로 아래 문제가 반복됩니다.

- 제목 아래 보조 설명이 길다.
- 같은 뜻의 안내가 제목, 부제, 가이드 박스, 허브 문구에서 중복된다.
- 카드 선택/버튼 클릭만으로 알 수 있는 내용을 다시 문장으로 설명한다.
- 페이지가 자기 구조를 과하게 설명한다.
- 감상형 서비스인데도 카피가 콘텐츠보다 먼저 보인다.

LoveBud는 기능 툴보다 **감상형/콘텐츠형 서비스**에 가깝다.
따라서 카피는 친절함보다 **밀도 조절**이 먼저다.

## 2. 전역 원칙

### 2.1 제목
- 제목은 **기본 1줄, 최대 2줄**까지만 허용한다.
- 3줄 제목은 금지한다.
- 제목은 페이지 역할이나 현재 행동을 바로 말해야 한다.
- 감정형 수식어를 길게 붙이지 않는다.

예:
- 허용: `공개 러브트리 둘러보기`
- 허용: `첫 순간 남기기`
- 금지: `좋아하는 마음이 시작된 장면부터 감정의 흐름을 따라 천천히 감상하는 공간`

### 2.2 부제 / 보조 설명
- 부제는 **기본 1문장**만 허용한다.
- **최대 2문장**, **최대 45자 내외**를 원칙으로 한다.
- 제목이 이미 충분하면 부제는 생략한다.
- CTA 바로 위/아래 보조 설명은 가능하면 제거한다.

### 2.3 구조 설명 제거
다음 유형은 원칙적으로 제거한다.

- `왼쪽에서 고르고 오른쪽에서 본다`
- `이 페이지는 ... 하는 공간이다`
- `여기서 ... 할 수 있어요`를 반복하는 문장
- 카드/패널/섹션의 배치를 해설하는 문장

구조는 레이아웃과 라벨로 이해되어야 한다.
카피는 구조 설명이 아니라 **현재 행동과 상태**만 남긴다.

### 2.4 하나의 블록에는 하나의 역할만 둔다
한 블록에서 아래를 동시에 하지 않는다.

- 제품 소개
- 사용법 설명
- 상태 안내
- 행동 유도

한 블록은 아래 중 하나만 맡는다.

- 제목
- 짧은 부제
- 상태 안내
- CTA

## 3. 상태 문구와 학습 문구 구분

### 3.1 상태 문구
상태 문구는 남긴다.
다만 짧고 즉시 이해 가능해야 한다.

허용 예:
- `불러오는 중`
- `아직 러브트리가 없어요`
- `트리를 찾을 수 없어요`
- `공개`
- `비공개`
- `한 순간 감상 중`

규칙:
- 현재 상태만 말한다.
- 해결 방법은 꼭 필요할 때만 1문장 덧붙인다.
- 감성 문장을 길게 붙이지 않는다.

### 3.2 학습 문구
학습 문구는 최소화한다.

학습 문구 예:
- `카드를 선택하면 오른쪽에서 볼 수 있어요`
- `이 페이지에서는 ... 할 수 있어요`
- `먼저 이걸 하고 다음에 저걸 하세요`

규칙:
- **첫 진입에서만 필요할 때 1회 노출**한다.
- 같은 뜻을 제목/가이드 박스/빈 상태/패널에서 중복 노출하지 않는다.
- 상호작용 자체가 충분히 명확하면 삭제한다.

---

## 4. 축소 기준

### 4.1 카드 위 설명
- 카드 리스트 위 설명은 **1문장 이내**.
- 카드가 이미 제목/이미지/배지로 의미를 전달하면 삭제한다.
- `천천히 열어보세요`, `감상해보세요` 같은 완충 문구를 반복하지 않는다.

### 4.2 버튼 아래 설명
- 원칙적으로 제거한다.
- 버튼 라벨이 불명확할 때만 **짧은 보조 1회** 허용한다.
- CTA 아래에서 다시 경로를 설명하지 않는다.

### 4.3 허브 설명 / 패널 설명
- 허브 상단 설명은 **1문장 또는 0문장**이 원칙이다.
- 선택 전 빈 상태와 선택 후 상태를 모두 긴 문장으로 설명하지 않는다.
- 허브는 설명 박스가 아니라 **현재 선택의 요약 공간**이어야 한다.

### 4.4 섹션 서문
- 섹션 제목만으로 충분하면 서문 삭제.
- 섹션 서문은 페이지당 많이 두지 않는다.
- 소개 페이지를 제외하면, 한 페이지에 긴 서문은 **최대 1개**만 허용한다.

## 5. 페이지별 우선순위

## 5.1 home
가장 먼저 줄인다.

이유:
- 첫인상을 결정한다.
- 히어로에서 이미 제목, 보조 문장, 플로우 칩, CTA, CTA 아래 설명이 겹치기 쉽다.

원칙:
- 제목 + 짧은 부제 + 대표 CTA 중심.
- 흐름 설명 칩과 CTA 아래 보조 설명은 우선 축소 대상.
- 제품 소개보다 **바로 시작 / 바로 감상**이 먼저 보여야 한다.

## 5.2 browse
두 번째로 줄인다.

원칙:
- 검색/필터/카드/허브만으로도 구조가 읽혀야 한다.
- `선택하면 오른쪽에서...` 같은 구조 설명을 우선 제거한다.
- 감상 허브 문구는 상태 중심으로만 남긴다.

## 5.3 my-trees
세 번째로 줄인다.

원칙:
- 관리 기능이 있어도 관리 툴처럼 보이지 않게 한다.
- 상단 설명, 선택 관리 설명, 모달 설명이 중복되면 줄인다.
- 사용자는 설명보다 **새 트리 생성 / 기존 트리 선택**을 먼저 봐야 한다.

## 5.4 intro
네 번째로 줄인다.

원칙:
- 소개 페이지는 다른 페이지보다 설명 허용 범위가 넓다.
- 다만 소개도 `무엇인지`, `어떻게 시작하는지`, `어떤 공간인지`를 모두 길게 반복하면 안 된다.
- 같은 메시지를 hero / what is / how to / value / CTA에서 반복하지 않는다.

## 5.5 detail
다섯 번째로 줄인다.

원칙:
- 상세는 감상 페이지이므로 설명보다 현재 순간과 연결 흐름이 먼저 보여야 한다.
- 따뜻한 문장은 가능하지만, 상태/예외 처리에서만 제한적으로 쓴다.
- 정상 상태에서는 긴 감성 설명보다 **제목, 메타, 기록 본문, 연결 순간**이 먼저다.

---

## 6. 톤 원칙

LoveBud 카피는 아래 인상을 유지한다.

- 담백함
- 조용한 몰입감
- 따뜻함
- 감상 중심

동시에 아래는 줄인다.

- 과한 자기소개
- 과한 친절함
- 지나친 기능 해설
- 레이아웃 해설
- 중복 감성 문장

문장 톤 규칙:
- 짧게 쓴다.
- 한 문장에서 한 메시지만 말한다.
- 감정을 과장하지 않는다.
- 사용자를 가르치듯 설명하지 않는다.
- 시스템 문장과 감성 문장을 섞어 길게 늘이지 않는다.

## 7. 바로 적용하는 판단 기준

문구를 남길지 지울지 헷갈리면 아래 순서로 판단한다.

1. 이 문구가 없어도 사용자가 다음 행동을 이해하는가?
   - 예: 삭제
2. 이 문구가 제목이나 버튼과 같은 뜻을 반복하는가?
   - 예: 삭제
3. 이 문구가 구조를 설명하는가?
   - 예: 삭제
4. 이 문구가 현재 상태를 짧게 알려주는가?
   - 예: 유지
5. 이 문구가 감상 몰입을 높이기보다 화면 밀도만 높이는가?
   - 예: 삭제

---

## 8. 후속 작업 적용 순서

후속 모델은 아래 순서로 줄인다.

1. 홈 히어로 중복 카피
2. 둘러보기 허브/가이드 문구
3. 내 트리 상단/관리 보조 문구
4. 소개 페이지 중복 섹션 문구
5. 상세 페이지 정상 상태 설명 문구
6. 예외/빈 상태 문구는 마지막에 정리

---

## 9. 한 줄 요약

LoveBud의 UI 카피는 **설명하는 문장**보다 **보여주는 구조와 행동**이 먼저여야 한다.

카피는 화면을 채우기 위해 쓰지 않는다.
카피는 지금 필요한 의미만 남기기 위해 쓴다.
