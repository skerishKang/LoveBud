사업 과제

02
Product Identity

LoveBud의 본질은 정보 정리가 아니라
팬 감정의 디지털 스크랩북입니다.

LoveBud가 다루는 것

  • 입덕 첫 영상과 특정 timestamp
  • 그 장면이 특별했던 감정 메모
  • 이어지는 팬심의 경로
  • 공유 가능한 입덕 루트

LoveBud가 피해야 할 것

  • 일반 북마크 앱
  • 차가운 데이터 관리 도구
  • 범용 커뮤니티 피드
  • 단순 영상 저장소
한 문장 정의: 나를 팬으로 만든 순간들을 영상과 감정으로 연결하는 입덕 경로 기록 서비스
03
Market Problem

팬들은 이미 기록하고 있지만,
감정의 경로를 담을 도구는 부족합니다.

링크는 남지만
맥락은 사라짐

왜 그 장면이 특별했는지, 어느 시점에서 입덕했는지 시간이 지나면 흐려집니다.

팬심의 순서가
보이지 않음

첫 장면, 다음 장면, 확신하게 된 장면이 하나의 경로로 연결되지 않습니다.

공유가
흩어짐

추천 영상 모음은 가능하지만 “내가 어떻게 팬이 되었는가”는 보여주기 어렵습니다.

LoveBud의 기회는 “영상 저장”이 아니라 “입덕의 맥락을 다시 감상 가능하게 만드는 것”에 있습니다.
04
Target User

초기 타깃은 전체 팬덤이 아니라
‘입덕 루트를 공유하는 팬’입니다.

1차 타깃

입덕 경험을 정리하고 싶은 팬

  • 아이돌·배우·드라마·영화·크리에이터 팬
  • “이 영상 보고 입덕했다”는 경험이 있는 사람
  • 다른 사람에게 좋아하는 대상을 영업하고 싶은 사람
핵심 욕구

좋아하게 된 이유를 보여주고 싶다

  • 내 입덕 순간을 예쁘게 남기고 싶다
  • 친구에게 왜 좋아하는지 보여주고 싶다
  • 신규 팬에게 입덕 루트를 안내하고 싶다

06
Core Loop

첫 순간을 심고, 3개의 감정 순간을 연결하고,
링크로 공유하게 만듭니다.

1첫 영상 입력입덕한 유튜브 영상과 timestamp를 남김
2감정 메모왜 이 순간이 특별했는지 기록
33 Moments 완성두 번째·세 번째 순간을 연결
4링크 공유다른 팬이 보고 다시 만들게 함
초기 성장은 검색 유입보다 공유 링크 기반으로 만들어야 합니다.
07
Validation Goal

대규모 런칭보다
30명의 실제 팬 검증이 먼저입니다.

30실제 팬 테스트 참여자
153개 순간 완성 트리
10링크 공유 사용자
1핵심 루프 검증

검증 질문

사용자가 첫 트리를 쉽게 만들고, 3개의 순간까지 기록하고, 완성된 트리를 공유하고 싶어지는가?

판단 기준

가입자 수보다 3 Moments 완성률, 공유 링크 복사율, 공유 링크 방문률을 먼저 봐야 합니다.

08
Product Priority

기술 구조 정리보다
공유 루프 완성이 먼저입니다.

Priority 1

Selected Tree Deep Link

공유 링크로 들어오면 해당 러브트리가 바로 보여야 합니다. 이 기능은 바이럴 루프의 입구입니다.

Priority 2

첫 트리 생성 UX

처음 들어온 사용자가 “첫 순간을 심기” 행동을 바로 이해해야 합니다.

Priority 3

샘플 러브트리

빈 서비스는 설득력이 약합니다. 운영자 예시 트리가 사용법을 설명해야 합니다.

리팩터링은 필요하지만, 지금 사업 임팩트가 가장 큰 작업은 공유 가능한 완성 경험입니다.
09
Revenue Model

초반에는 무료 공유,
이후 Plus와 팬덤 큐레이션으로 확장합니다.

Step 1

무료 공개 트리

누구나 만들고 공유하게 하여 사용 사례와 공개 콘텐츠를 확보합니다.

Step 2

Plus 기능

비공개 보관, 고급 테마, 트리 개수 확장, export, 워터마크 제거로 과금합니다.

Step 3

팬덤·크리에이터용

입덕 가이드 페이지, 팬덤 큐레이션, 임베드 가능한 러브트리로 확장합니다.

지금 결제부터 붙이면 안 됩니다. 먼저 “왜 만들고 공유하는지”를 증명해야 합니다.
10
Go-to-Market

“앱 출시”가 아니라
“입덕트리 3 Moments 챌린지”로 시작합니다.

캠페인 메시지

당신의 입덕 첫 순간은 무엇이었나요?
나를 팬으로 만든 영상 3개로 러브트리를 만들어보세요.

참여 방식

  • 첫 영상과 timestamp 입력
  • 감정 메모 작성
  • 두 번째·세 번째 순간 추가
  • 러브트리 링크 공유
내 입덕 루트가 다른 팬의 시작점이 된다는 메시지가 가장 강한 확산 동기입니다.
11
Operating Strategy

CTO 운영은 작게 나누고,
하나씩 검증하고, 사업 루프와 연결해야 합니다.

개발 운영 원칙

  • main 직접 수정 금지
  • 한 PR에 하나의 목적만 담기
  • 기능·UI·문서 작업 분리
  • Preview 또는 test slot 기준 검증

사업 판단 기준

  • 사용자가 만들 수 있는가?
  • 사용자가 공유할 수 있는가?
  • 공유받은 사람이 이해하는가?
  • 다시 만들고 싶어지는가?
