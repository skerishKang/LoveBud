Product Prompt

🛡️ Safety Note Contract

The Product Prompt's safety note contains the non-negotiable instructions that must appear in any live provider's prompt. The safetyNote returned in every response echoes these instructions back to the user, ensuring transparency.

🇬🇧 English Canonical

This is an AI-generated suggestion. The provider was instructed to: - Use only the user-entered excerpt/memo text (no fetching, no inference) - Produce a transformative summary, not a verbatim reproduction - Return short, editable suggestions, not final saved content - Refuse to invent facts about the source beyond the user's text - Refuse to handle credentials, tokens, API keys, or PII - Refuse to bypass copyright or claim the source was fully read Always review the suggestion before saving it to your LoveTree.

🇰🇷 Korean Canonical

이 제안은 AI가 생성한 초안입니다. 다음 사항이 provider에 지시되었습니다: - 사용자가 직접 입력한 발췌/메모 텍스트만 사용 (자동 fetch 금지) - 원문 복제가 아닌 변형된(transformative) 요약만 생성 - 짧고 편집 가능한 제안을 반환하며 최종 저장 콘텐츠가 아님 - 사용자 입력 외의 사실/정보를 임의로 만들어내지 않음 - 자격증명, 토큰, API key, PII는 절대 처리하지 않음 - 저작권 우회 또는 원문을 모두 읽었다는 주장은 하지 않음 LoveTree에 저장하기 전 반드시 제안 내용을 직접 검토해 주세요.
📋 Safety Note Invariants (7 rules)
  1. The safety note must be present in every provider response — not only on error.
  2. The safety note must not be empty, and must not be replaced with marketing copy.
  3. The safety note must contain at least one of: "review", "검토", or equivalent in the request language.
  4. The safety note must not contain any credential, API key, or environment variable name.
  5. The safety note language should match requestedLanguage when possible.
  6. If the provider returns a response without a safety note, the adapter must inject the canonical safety note (never silently drop it).
  7. The safety note is the only part of the response the user can rely on for transparency.
Input Boundary

📤 Allowed vs Prohibited Prompt Inputs

✅ Allowed Inputs

  • 📝 User-entered excerpt
  • 📋 User-entered summary
  • 🗒️ User memo
  • 🔗 Source URL string (attribution only)
  • 🌐 Requested language (ko/en)
  • 🎭 Desired tone (casual/polite/emotional)
  • 📏 Max output length

🚫 Prohibited Inputs

  • 🔑 API keys
  • 🆔 Auth / session tokens
  • 👤 Hidden user profile / PII
  • 🌲 Unrelated LoveTree data
  • 💬 Private messages not in Scout Draft
  • 📰 Full article text (no crawling)
  • 🔒 Paywalled / private content
  • 💾 Raw browser storage / cookies
  • 🔥 Firebase credentials
  • 🗄️ DB records not selected by user

Contract Overview

📌 Key Contract Guardrails

🔒

Copyright Boundary

No automatic article retrieval, no full-text reproduction, no long verbatim copying. Only transformative summaries. User review required before save.

🛡️

Safety Boundary

No hidden data inference, no credential handling, no source impersonation. Every response must include a safetyNote.

🎯

Validation Rules

emotionTags max 4 items, each ≤20 chars. Invalid provider responses map to PROVIDER_ERROR. No raw model response applied directly to UI.

🌐

Language & Tone

requestedLanguage (ko/en) and desiredTone (casual/polite/emotional) guidance. Unsupported values fall back safely. No invented facts beyond user input.

✨

UI Application

Editable fields only. User must click "저장" (Save) to persist. No auto-save. Manual save always available even when suggestion fails.

⛔

Non-Goals

No live provider implementation, no API keys, no external URL fetch, no crawler, no auto-save, no DB/schema migration, no Browse #1661 work.

Verdict
📜

The prompt and response contract is ready to guide a future live-provider adapter skeleton, but live provider calls remain out of scope.
